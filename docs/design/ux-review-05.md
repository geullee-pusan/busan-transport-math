## P1 — 첫 학생 테스트 전에 고칠 것

### 운행 화면
| # | 문제 | 고칠 방법 |
|---|---|---|
| P1-1 | **④ 빈칸을 맞힌 뒤 답을 처음부터 다시 쳐야 한다.** 빈칸 `5`를 넣고 답 내기 → 답 칸이 비고 "ⓘ 이제 답을 써요." 아이는 이미 답했다고 느낀다. | 빈칸이 맞으면 답 칸에 전체 답(853)을 채워 보여주고 단추를 `853 — 답 내기`로 바꾼다. 아이가 한 번 더 누르면 채점. 판단 질문(blankThen)이 있는 문제만 지금처럼 다음 질문을 연다. |
| P1-2 | **정답 문구가 칸 진행과 이어지지 않는다.** 정답마다 "✓ 맞았어요"뿐이고, 띠의 칸이 채워지는 것과 연결되는 말이 없다. | `✓ 맞았어요 · 한 칸 앞으로`(반 칸이면 `· 반 칸 앞으로(서행)`). 칸이 채워지는 0.4초 연출을 띠에서 함께. 칸에 안 들어가는 정답(2단계 미만 등)은 `✓ 맞았어요`만. |
| P1-3 | **남은 칸을 내림으로 센다.** 1칸 반을 채운 상태에서 홈은 "다대포해수욕장역까지 **2칸**", 띠의 aria는 "2칸 남음"이다. 실제로는 2칸 반이 남았다. 다음 운행에서 2칸을 채우고도 도착하지 않으면 약속이 깨진다. | `2칸 반`으로 쓴다(반 칸 단위를 그대로). `Math.floor`/`Math.ceil`을 섞어 쓰지 말고 halves로 계산하는 함수를 하나만 둔다. |
| P1-4 | **진행 띠가 3차안과 다르다.** 지금은 역 이름 + 작은 칸 4개(34×12px)뿐이다. 출발역 점, 도착역 점, 차량, 얇은 "40역 중 N역" 막대가 없다. | 3차안 5.1절: `앞 역 ●━[■][◧][ ][ ]━○ 다음 역` + 차량 그림 + 아래 6px 전체 막대. 칸 크기는 최소 40×16px. |
| P1-5 | **숫자 단추의 누르는 영역이 너무 작다**(폭 16~30px, 높이 31~40px). 문장을 손가락으로 따라 읽다가 말풍선이 자주 뜰 것이다. "만든 숫자" 글자가 숫자 아래에 붙으면서 **숫자와 단위가 벌어진다**("앞 4 ⎵⎵ 량에만"). | ① 숫자 단추에 투명한 48px 누르는 영역(`::after`)을 두되, 길게 누르기(0.4초)로만 말풍선을 띄워 읽는 손가락과 구분한다. ② "만든 숫자" 글자는 문장 흐름 밖(절대 위치, 숫자 아래)에 두어 줄 안의 간격을 바꾸지 않는다. |
| P1-6 | **고른 선택지와 "답 내기" 단추가 같은 모양**(진한 바탕 + 흰 글자)이다. 고르기 문제에서는 "답 내기"에 고른 답이 나오지 않는다(숫자 문제는 `3명 — 답 내기`로 잘 나옴). | 고른 선택지 = 흰 바탕 + 굵은 테두리 4px + ✓ 표시. 답 내기는 지금처럼 진한 바탕. 고르기에서도 `(가) — 답 내기`. |
| P1-7 | **(가)(나) 두 상황이 한 문단에 이어져 있다.** "어느 쪽이에요? (가) 24명이 1호선 8량에… (나) 24명이…"처럼 읽힌다. | 문제 문장은 물음 한 줄, 두 상황은 그 아래 **두 장의 카드**로 줄을 나눠 둔다. 선택 단추에는 (가)/(나)만. |
| P1-8 | **여러 칸 답의 이유 칩이 3열로 끼어 4줄로 꺾인다**("똑같이 / 나눈 조각 / 중 / 하나예요"). | 문장형 선택지는 **한 줄에 하나씩 전체 폭**. 짧은 칩(예/아니요, 숫자)만 가로로. |
| P1-9 | **분수를 "1/4"로 쓰고, "/" 키로 입력한다.** 3학년은 빗금 표기를 배우지 않았다(교과서는 위아래 표기). | 문장 안 분수는 위아래로 쌓아 그린다(작은 분수 글꼴, 줄 간격 유지). 입력은 1차안 6절의 분수 틀(위·아래 칸). "/" 키는 없앤다. |
| P1-10 | **힌트 ② 관문 칩이 모든 문제에서 같다**("식 세우기 / 첫 계산 / 모르겠어요"). `258 + 595 = ?`처럼 식이 이미 있는 문제에서 "식 세우기"는 뜻이 없다. | 템플릿에 관문 칩을 정하는 칸을 둔다. 맨 계산은 `일의 자리 / 받아올림 / 모르겠어요`처럼. 4차안의 **길 고르기 카드**(T3-1 등)도 아직 없다. |
| P1-11 | **틀린 답 취소선 색 `#9AA5AD`는 흰 바탕에서 대비가 약 2.5:1**이다. 하린 유형은 자기 답을 확인하고 싶어 한다. | `#5E6B76`(4.8:1) + 취소선. |
| P1-12 | **"이 문제 이상해요" 이유에 "부산 사실이 틀려요"가 없다**(지금: 숫자/문장/답/그림). 하린이 신고 버튼을 원한 이유가 바로 틀린 부산 사실이다. | 이유 칩에 `부산 이야기가 틀린 것 같아요` 추가. 신고하면 그 문제의 real 숫자 목록도 함께 저장(4차안 6.2). |
| P1-13 | **운행 중 쉬기 번호를 `window.prompt`로 받는다.** 브라우저 기본 창이라 **번호가 그대로 보이고**, 아이 옆에서 부모가 넣기 어렵다. 처음부터 다시 하기도 같다. | 앱 안의 가린 입력(●●●●) + 숫자 키패드 시트. 부모 화면 진입과 같은 컴포넌트를 쓴다. |
| P1-14 | **연습장** [화면 + 코드]: ① 화면 크기가 바뀌면(돌리기, 분할 화면) 캔버스 크기를 다시 정하면서 **그린 것이 지워진다**(`canvas.width =` 대입). 3차에서 정한 "돌려도 지워지지 않게"와 어긋난다. ② 세로셈 틀, 유형별 기본값, 되돌리기, 틀린 문제의 연습장 보존이 없다(4·5차 결정). ③ 연습장이 화면 아래 45% 높이로 떠서 키패드를 가린다. | ① 크기 바꿀 때 그림을 옮겨 그리거나, 획을 배열로 저장했다가 다시 그린다. ② 세로셈 틀부터(받아내림 두 번 이상이면 기본값). ③ 가로에서는 B 영역(문제 아래)에만 펼친다. |

- **해설 시트는 글만 있다.** 4차안의 "문장마다 그림 한 장"과 "마지막 장 = 결론 + 같은 답 확인"이 없다. 지금 구조(탭, 넘기기 점, 앞/다음)는 좋다.

## [코드]로만 본 입력에 대한 메모
- **여럿 고르기**: 안내 "맞는 것을 모두 골라요." 14px 회색 → 18px 본문색. 고른 칩 = 진한 채움만(✓ 없음) → P1-6과 같이.
- **순서**: 누른 차례가 위 칸에 `→`로 쌓이고 "하나 지우기"가 있다. 좋다. 이미 고른 항목에 차례 번호(①②)를 붙이면 더 분명하다.
- **색칠**: 칸 56px ✓, 칠한 수를 보여주지 않음 ✓. 색칠 칸이 문제 그림(B)이 아니라 입력 영역(C)에 따로 그려진다. 문제 그림의 열차 칸을 직접 누르는 쪽이 개념과 맞다(그림 = 입력).
- **식**: 연산 칩 4개 + 칸 3개 ✓(F1 반영). 연산을 안 골랐을 때 `○`로 보인다. 빈 연산 자리는 점선 네모가 더 분명하다.
- **"어떻게 어림했어요?"**: 6열 미니 키패드(48px)와 선택지가 한 칸 안에 쌓인다. 가로 1180에서 C 폭(약 440px)에 6열이면 키가 약 64px라 괜찮다. 다만 이 칸이 비어 있을 때 선택지가 흐려지는 이유를 글로 알려 주는 안내가 없다 → `먼저 어떻게 어림했는지 써요` 한 줄.
- **어림 먼저**: 어림 칸 + 별도 미니 키패드 + 본 키패드가 동시에 보이면 키패드가 두 개다. 어림 확인 뒤 미니 키패드가 사라지는 것 ✓. 어림 전에는 본 키패드를 **숨기는** 쪽이 낫다(지금은 흐리게 보임).
