# UX 자문 8차 — "허접·성의없다" 진단과 화면별 개선안 (배치도 포함)

> 작성: UX 자문, 2026-10-04
> 근거: `docs/design/knowledge.md`(웹 조사, 출처 포함), 최신 배포판을 헤드리스 Chrome으로 **정확히 1480×924·924×1480**으로 캡처한 25장(처음 화면 → 시승 6문제 → 시승 일지 → 홈 → 보통 운행(오답·힌트·연습장·넘기기·해설) → 일지 → 차고 → 세로 홈·운행), 시각 자문 1~3차, 학생 #1(도윤) 배포판 체험 ①~⑦.
> 이 문서는 **배치·흐름·크기**를 정한다. 모양·색·그림 체계는 시각 자문 문서(`docs/visual/`)를 따르고, 시각 쪽 확인이 필요한 곳은 **[시각 확인]** 으로 표시했다. 시각 자문에 같은 내용을 보냈다.
> 캡처는 이 대화의 임시 폴더에 있다(배포물 아님). 사용자 브라우저 저장소는 쓰지 않았다(새 임시 프로필).

## 0. 한 줄 결론
"허접하다"의 뿌리는 색이나 글꼴보다 **세 가지**다.
1. **그림이 없는 화면**: 홈·차고·일지·첫 화면이 상자와 글자뿐이다. 기차를 좋아하는 아이에게 차량 그림이 한 장도 없다.
2. **비어 있는 화면**: 운행 화면은 가로 1480×924에서 문제 판과 입력 판이 위쪽 약 300~680px만 쓰고 나머지가 빈 바탕이다. 늘린 2단은 큰 화면 가이드가 "가독성·공간 모두 나쁨"이라고 한 바로 그 배치다.
3. **맥락 없는 맨 식**: "68 × 7 = ?"가 큰 흰 판에 혼자 있다. 학습 앱 비평의 "평범하고 건조한 드릴"(Prodigy 평가)과 같은 인상이다.

**해법의 원칙**: 빈 곳을 장식으로 채우지 않는다. 연구에서 효과가 가장 큰 원칙이 "관계없는 흥미 요소 빼기"(Mayer 일관성, d = 1.66)다. 그래서 **풀이 화면은 학습에 쓰이는 것(장면 그림·작업대·답·힌트)으로 채운다.** 풍성한 그림(차량·지도·지형·역명판)은 **풀이 밖**(첫 화면·홈·일지·차고·출발 장면)에 쓴다. "성의 있어 보이는 앱"의 무게는 그쪽에 둔다.

## 1. 화면별 진단 (캡처 기준)

| 화면 | 아이가 "허접·성의없다"고 느낄 지점 | 근거·관찰 |
|---|---|---|
| **처음 화면** | 가입 양식처럼 생겼다. 가운데 좁은 단(약 830px)에 제목·입력 칸·색 동그라미 5개·안내 상자·점선 단추가 세로로 있고, 양옆 약 650px가 빈 바탕이다. 부산도 기차도 없다. 차량 색은 **동그라미**라 "무엇의 색"인지 안 보인다 | 학생 ①. 첫인상이 앱 전체 인상을 정한다 |
| **시승·운행 문제 화면** | ① 맨 식 `68 × 7 = ?`가 820×105 흰 판에 혼자 있다. ② 그 아래 약 600px가 빈 바탕이다. ③ 오른쪽 키패드 판이 화면에서 가장 큰 덩어리라 "계산기 앱"처럼 보인다. ④ 비교 문제의 `>` `<` `=` 단추는 72px 상자 안에 18px 기호다. ⑤ 시승에는 진행 표시가 없다(몇 문제 남았는지, 어디로 가는지) | 캡처 L02·L03·L06. 큰 화면 가이드: 늘린 배치 비권장, 62:38 또는 70:30 |

| **연습장** | 화면 아래 45%에 떠서 키패드를 덮는다. 빈 노란 판에 아무 틀이 없다 | 캡처 L10 |
| **해설 시트** | 1100×550 흰 판에 문장 한 줄. 판이 내용보다 다섯 배 크다. 뒤의 "다음 문제" 단추가 반쯤 가려진다 | 캡처 L13 |
| **일지** | 글머리표 3줄 + 단추 2개, 나머지 화면이 빈 바탕. 큰 소식 그림이 없다. 시승 일지는 "오늘 0 m 달렸어요 · 모두 0 m" | 캡처 L04·L14 |
| **홈** | 노선도가 지형 없는 흰 판 위 선과 점이다(형제 앱에는 육지·바다·산 색이 있음). 1호선이 흰 점 40개로 **사다리 무늬**. 역 이름은 양 끝 둘뿐. 다른 노선은 회색 점선 낙서처럼 보인다. 오른쪽 칸은 단추 줄 아래 약 480px가 비어 있다 | 캡처 L05. 시각 1차 3위와 같음 |
| **차고** | 11장 카드가 **모두 글자뿐**, 10장은 점선 상자에 "면허가 ○○ 단계가 되면 받아요"가 반복된다. 수집 화면인데 모을 것이 안 보인다 | 캡처 L15. 시각 1차 6절 차량 그림이 아직 안 들어옴 |

## 2. 운행 화면(문제 화면) — 배치 결론

### 2.1 가로 1480×924: **"장면 + 작업대" 62 : "답 + 도움" 38**
늘린 2단(문제 판 | 키패드 판)을 버리고, 큰 태블릿의 supporting pane으로 바꾼다. **빈 아래 절반은 작업대(연습장)가 된다.** 종이 문제집의 "문제 위, 풀이 공간 아래"와 같은 구조다(Prodigy의 "넉넉한 풀이 공간"도 같은 방향).

```
1480 ──────────────────────────────────────────────────────────────────────────────
┌ A. 노선 띠 (높이 104) ───────────────────────────────────────────────────────────┐
│ ✕   ① 다대포항 ●━━[■][■][◧][ ]━━○ 낫개            ▕▔▔▔▔▔▔▔▏ 40역 중 3역   [쉬기] │
│      (앞 역)   🚌 칸 4개(56×22)    (다음 역, 굵게 24)   전체 막대 + ▲ 내 위치            │
├──────────────────────────────────────────────────┬───────────────────────────────┤
│ B. 문제 장면 (폭 약 900)                           │ C. 답과 도움 (폭 약 540)          │
│ ┌ 문제 판 ─────────────────────────────── 🔊 ⚑ ┐ │ ┌ 도움 자리 (높이 가변, 최대 300) ┐ │
│ │ 어느 날 앞 4량에 217명이 탔고, 뒤 4량에는…      │ │ │ 힌트 카드 ①②③④가 여기 쌓임     │ │
│ │ (문장 26px, 최대 3줄)                         │ │ │ 또는 피드백: ⏸ 버스가 잠깐 …   │ │
│ │ ┌ 장면 그림 (고정 배율 K=1.5, 높이 최대 300) ┐ │ │ │ 또는 정답: ✓ · 한 칸 앞으로    │ │
│ │ │ [▭▭▭▭]=[▭▭▭▭]  수치 라벨은 그림 칸 옆에     │ │ │ └──────────────────────────────┘ │
│ │ └────────────────────────────────────────┘ │ │                                  │
│ └──────────────────────────────────────────────┘ │ ┌ 답 칸 (높이 84) ────────────┐ 명 │

│ │  세로셈 틀 / 빈 종이 / 수직선 틀 (문제 종류별 기본값)   ││ ┌ 키패드 3×4 (키 150×84) ───┐  │
│ │  펜·손가락. 화면 크기가 바뀌어도 지워지지 않음          ││ │ 1  2  3                       │  │

│                                                  │ │ 7  8  9                       │  │
│                                                  │ │    0  ⌫                       │  │
│                                                  │ └──────────────────────────────┘  │
│                                                  │ [ 476 — 답 내기 ] (높이 88, 전체 폭)│
└──────────────────────────────────────────────────┴───────────────────────────────┘
```
- **D 도구 막대를 없앤다.** 화면 아래 한 줄(88px)을 다른 곳으로 나눈다.
  - 🔊 읽어 주기·⚑ 신고 → 문제 판 오른쪽 위(문장 바로 옆, 근접성)
  - 연습장 → 작업대 자체가 늘 보임. 틀 바꾸기·되돌리기·지우기는 작업대 머리
  - 힌트 → C의 도움 자리 맨 위 `[힌트 보기]`(84px). 두 번 틀리면 이 단추가 굵어짐(지금 규칙)
  - "아직 몰라요"(시승) → 같은 자리
  - 쉬기(부모) → A 띠 오른쪽 끝(작게, 부모 번호 필요)
- **답 쪽을 아래로 붙인다.** 답 칸·키패드·답 내기가 C의 아래쪽에 붙는다. 아이 손이 가장 정확한 곳(아래·가운데)에 자주 누르는 것을 둔다.
- **도움 자리(C 위쪽)** 하나에 힌트·피드백·정답 소식이 차례로 나온다. **서랍이 없어진다** → 힌트를 보면서 키패드를 쓸 수 있다(학생 ④ 해결). 자리 높이는 내용만큼(최대 300, 넘치면 그 안에서만 스크롤). 키패드는 절대 밀려나지 않는다.
- **장면 그림**은 시각 3차 1-4의 고정 배율(K = 1.5)로 그린다. 높이 최대 300. 그림이 없는 문제는 작업대가 그만큼 커진다.
- **작업대**는 문제 종류별 기본값(4차 결정)을 따른다: 계산 = 세로셈 틀, 길·도형 = 그림 위 투명 층(이때만 장면 위로 올라감), 그 밖 = 빈 종이. 틀린 문제의 작업대는 보존.

### 2.3 크기 (아동 터치 연구 반영)
| 대상 | 지금 | 제안 | 근거 |
|---|---|---|---|
| 키패드 키 | 150×72 | **150×84** | 아동 1.8cm(≈84px) 이상에서 나이 차 사라짐(Woodward 2017) |
| 답 내기·출발 | 80 | **88** | 같은 근거 + 가장 자주 누름 |
| 선택지 | 72 | **84**, 기호 선택지(`> < =`)는 글자 **40px** | 지금 기호 18px — 단추만 크고 기호는 작다 |
| 도구(🔊 ⚑ 등) | 72 | 보이는 크기 56~64 + **활성 영역 84** | 활성 영역을 보이는 경계보다 크게(Anthony 2013) |
| 화면 가장자리 | 틈 12~16px | 가장자리 단추는 **가장자리까지 활성 영역** | 가장자리 틈에서 놓침 2배(Anthony 2013) |

### 2.4 홀드오버(전환 직후 같은 자리 다시 누름) 막기
- 지금 시각안대로 "답 내기" 자리에 "다음 문제"가 나오면, 아이가 답 내기를 두 번 누르는 순간 **정답 소식과 칸 진행을 못 보고 넘어간다**(7~10세 홀드오버는 성인의 약 7배, 태블릿 9.9%).
- 제안: 답을 낸 뒤 **0.6초 동안 그 자리는 눌러도 반응하지 않는다**(보이는 변화 없음). "다음 문제"는 0.6초 뒤에 같은 자리에서 활성화된다. 키보드 Enter도 같은 0.6초를 지킨다(오늘 들어간 키보드 입력).

### 2.5 맨 식 문제
- 커리큘럼이 계산식 53개에 교통 장면을 붙이는 중이다. 이건 맞는 방향이다(Duolingo Math: 같은 연산을 맥락마다 다른 그림으로. NN/g: 맥락 없는 숫자는 혼란).
- 장면을 붙인 뒤에도 남는 **정비창 점검(맨 계산 묶음)** 은 "정비창"이라는 장소감을 **A 띠와 작업대**에 준다. 문제 판에는 장식을 넣지 않는다.
  - A 띠: `🏭 정비창 · 곱셈 점검 [■][■]` + 정비창 그림 띠(차고 지붕 선, 높이 104 안) **[시각 확인]**
  - 작업대: 세로셈 틀을 기본으로 크게 연다. 맨 식에서는 작업대가 화면의 주인공이다.
- 시승 첫 문제는 맨 식이 아니라 **교통 장면 문제**로 시작하기를 권한다. 첫 문제가 앱의 얼굴이다(보호자 피드백의 시작점).

## 3. 학생 #1 ①~⑦ 결정

| # | 질문 | 결정 |
|---|---|---|
| ① | 첫 화면이 양식 같다 | **꺼진 노선도 + 이름 칸**(3차 합의안)으로 한다. 배치는 4.1절 |
| ② | 노선 띠·차량 이동·진행 막대 배치 | 2.1절 A 띠. 칸 4개 56×22(시각안 44×18보다 크게 — 띠가 화면의 진행 주인공이 됨), 앞 역·다음 역 이름 24px, 차량 그림이 칸 위를 움직임, 오른쪽에 40역 막대 + ▲. 시승에서는 칸 대신 **"시승 운행 · 문제 3 / 약 8"**(끝이 정해지지 않으면 "약") |
| ③ | 여러 칸 입력에서 "38"이 "388"이 됨 | **자동 다음 칸 이동은 하지 않는다**(자릿수를 모르는 칸에서 엉뚱한 칸으로 넘어가면 더 헷갈림). 대신 ① 지금 쓰는 칸 = 4px 테 + 커서 + 칸 위 이름표 `지금 쓰는 칸` ② 키패드 바로 위에 `→ 1km 칸에 써요`(어느 칸에 써지는지 손 가까이에서) ③ 각 칸에 **최대 자릿수**(maxDigits)가 있으면 그 이상은 안 들어가고 칸이 한 번 흔들림 없이 테만 굵게 ④ 답 내기 단추에 칸별 요약 `39개 · 9개 — 답 내기`. 자릿수가 고정인 칸(시각의 "분" 2자리 등)만 다 차면 다음 칸으로 넘어간다 |
| ④ | 힌트 서랍이 숫자판을 덮음 | 서랍을 없애고 C의 **도움 자리**로(2.1절) |
| ⑤ | 역 목록을 다 보여 주면 그냥 센다 | **단계로 나눈다.** 1~2단계(개념 처음)는 역을 다 그린다 — 세는 것이 곧 개념이다. 3단계 이상은 **축약 노선**(양 끝 역 + 처음 두 역 + `⋯ 역 9개 ⋯` + 끝 역)으로 그리고 "펼치기"를 두지 않는다(펼치면 다시 셈). 축약 표시는 그림 문법으로 한 모양 **[시각 확인]** |
| ⑥ | 시승이 "아직 몰라요" 3번에 8문제로 끝나는데 안내가 없다 | ① A 띠에 `시승 운행 · 문제 3 / 약 8` ② 일찍 끝날 때 마지막 문제 뒤 도움 자리에 `여기까지면 충분해요. 출발역을 정했어요.` ③ 시승 일지 첫 줄에 `○문제로 출발역을 정했어요` |
| ⑦ | 계산 문제의 힌트 ①이 문제를 다시 읽기만 함 | 장면을 붙이면서 ①도 "그림에서 무엇을 보면 되는지"를 짚게 바꾼다(예: `앞 4량과 뒤 4량을 따로 세어 봐요`가 아니라 `앞 4량에 몇 명, 뒤 4량에 몇 명인지 그림에서 찾아봐요`). ①은 전략을 말하지 않는 규칙(4차 F3)은 그대로 |

### 4.1 처음 화면 (가로) — "꺼진 노선도 + 이름"

- 차량 색을 고르면 **왼쪽 지도 위의 내 차량 색이 바로 바뀐다.** 고르는 행동이 결과로 보인다.
- 세로: 위 노선도 55%, 아래 이름·차량·출발.

### 4.2 홈
- 노선도에 **지형 색**(형제 앱과 같은 육지·바다·산)을 깐다. 지형은 "장식"이 아니라 노선도의 일부라 일관성 원리와 부딪히지 않는다(풀이 화면이 아님).
- 첫 보기는 **목적지 앞뒤 약 6역 확대**(6차 결정) + 구석 미니맵. 확대 보기에서는 역 이름이 보여 "사다리 무늬"가 역 이름 있는 노선이 된다.
- 오른쪽 38% 칸을 위에서부터 채운다.
  1. **역명판 카드**(다음 역): `[①] 다대포해수욕장` 큰 글자 40, 아래 `← 시작 · 다대포항 →`, 진행 칸 4개. 지하철 역명판 모양을 빌린 이 앱의 상징 **[시각 확인: 실제 부산교통공사 역명판 모양을 그대로 베끼지 않는 선에서]**
  2. `[ ▷ 출발 ]` 전체 폭 88(시각 3차 1-6)
  3. `[급행] [도전 운행] [차고]` 같은 폭 한 줄
  4. **내 차량 카드**: 지금 면허 차량 그림 + 이름 + 금 도장 칸(작게). 누르면 차고
  5. 남는 아래: 오늘 운행 수("오늘 2번 중 1번 했어요"), 비면 비운 채로 둔다(억지로 채우지 않음)

### 4.3 운행 일지
```
┌ 제목: ① 다대포항 → 낫개 가는 길 ───────────────────────────────────────────┐
│ ┌ 큰 소식 (폭 전체, 높이 약 360) ─────────────────────────────────────────┐ │
│ │ 구간 그림이 크게: 앞 역 ●━[■][■][■][ ]━○ 다음 역, 내 차량이 칸을 지나가는 │ │
│ │ 연출. 역 개통이면 점등 연출 + 역명판. 승급이면 면허증 + 차량 그림          │ │
│ └──────────────────────────────────────────────────────────────────────┘ │
│ [아이콘] 새로 켜진 역 …     [아이콘] 금 도장 +2 [차량 작은 그림 ■■□□□]      │
│ [아이콘] 오늘 600 m · 모두 3 km      [아이콘] 다음 운행 임시 정차 1곳 ▸       │

```
- 일지는 **보상 화면**이라 그림을 아끼지 않는다(풀이 화면이 아님).
- "0 m" 줄은 보이지 않게(3차 원칙: 해당 없는 줄은 뺀다).

### 4.4 차고
- 카드마다 **차량 그림**(시각 1차 6절 원형). 못 얻은 카드는 **윤곽만**(점선 바닥) + 조건 — 점선 상자 안의 글자 반복이 아니라 "모을 것"이 보이게.
- 위쪽에 **지금 운행 차량 큰 그림**(폭 전체, 높이 약 200) + 이름 + 금 도장 칸. 아래 카드 격자.
- 카드 격자: 4열 → 가로 1480에서 5열(카드 260×300). 카드 그림 영역 120px.

### 4.5 해설 시트
- 높이를 **내용만큼**(최소 280, 최대 화면 60%). 문장 + 그림이 한 장에 들어가는 크기.
- 시트는 C 영역 위로만 올라온다(B의 문제와 작업대는 보이게) — 해설을 보며 자기 풀이와 비교할 수 있다.
- 마지막 장은 결론 한 문장 + 다른 풀이와 답이 같다는 확인(5차 결정).

### 4.6 시승 운행
- 첫 문제: 교통 장면 문제(2.5절).
- A 띠: `시승 운행 · 문제 3 / 약 8` + 차량 후보 그림(`지금 급행버스 후보!` — SPEC 3.5).
- 일지: 4.3과 같은 틀, 큰 소식 = "출발역과 시작 차량" + 미리 켠 역이 지도에서 켜지는 연출.
