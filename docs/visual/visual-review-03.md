## 1. 고칠 것 (우선순위 순)

### 1-1. 채점 뒤 입력 칸이 "아직"(점선) 모양이 된다 — 선 문법 위반 · 쉬움
- 본 것: 고르기 문제에서 (가)를 고르고 답을 내면, `.input.locked`가 되면서 **(가)·(나)·답 내기가 모두 점선 + 옅은 바탕**으로 바뀐다. 고른 (가)의 ✓ 배지도 회색이 된다.
- 왜 문제인가: 점선은 "아직"이다. 채점이 끝난 칸은 "끝남"인데 "아직 못 누름"처럼 보여서, 아이는 답이 안 들어갔다고 느끼거나 무엇을 골랐는지 흐려진다. 하린 유형은 자기 답을 다시 확인하고 싶어 한다.
- 고칠 방법: 잠금을 두 가지로 나눈다.
  - `.input.waiting`(아직 열리지 않음: 어림 전 계산 칸 등) = 지금처럼 점선.
  - `.input.done`(채점 끝남) = **실선 그대로**, 고른 칸은 4px + 진한 ✓ 배지 유지, 고르지 않은 칸은 테두리 1.5px `--line-mute`(실선), 답 내기는 숨기고 그 자리에 "다음 문제"(72~80px, 전체 폭 — UX 05 P2와 같은 자리). `pointer-events: none`만 같다.
  ```css
  .input.done { pointer-events: none; }
  .input.done .choice:not(.chosen), .input.done .chip:not(.chosen), .input.done .key { border: 1.5px solid var(--line-mute); background: var(--paper); color: var(--ink-2); }
  .input.done .chosen::after { background-color: var(--ink); }
  .input.done .submit, .input.done .keypad { display: none; }
  ```

### 1-2. 세로(924×1480)에서는 기준 기기 크기가 적용되지 않는다 · 쉬움
- 본 것: 세로에서 키 높이 64, 도구 아이콘 24, 피드백 아이콘 28, 문제 24px(가로는 72 / 28 / 32 / 26). `style.css`와 `tokens.css`의 기준 기기 문턱이 `min-width: 1300px`라 세로 924 폭에서는 꺼진다.
- 고칠 방법: 문턱을 `@media (min-width: 1300px), (min-width: 900px) and (min-height: 1300px)`로(긴 변으로도 잡기). `assets/tokens.css`는 이렇게 고쳐 두었다. `style.css` 328행 기준 기기 절도 같은 조건으로.

### 1-3. "만든 숫자" 글자가 숫자와 단위를 벌린다 · 쉬움(시각) — UX 05 P1-5 그대로 남음
- 본 것: `24 ⎵⎵⎵ 명`, `4 ⎵⎵ 량에만`. `.virtual-wrap`의 폭이 70px인데 숫자는 32px이다. "만든 숫자"(16px)가 숫자 아래 글자 흐름 안에 있어 폭을 차지한다. SPEC 9.3 "숫자와 단위는 붙여 쓴다"를 어긴다. 밑에 붙은 글자는 다음 줄과도 가깝다.
- 고칠 방법(시각 제안): 처음 세 번 안내를 숫자 밑에 달지 말고, **문제 판 맨 위 한 줄 꼬리표**로 낸다: `[· · ·] 점점이 밑줄 = 만든 숫자예요`(16px, `info` 아이콘). 숫자에는 점점이 밑줄만 남는다. 숫자 밑에 꼭 두려면 `position: absolute; left: 50%; transform: translateX(-50%); top: 100%; white-space: nowrap`으로 흐름 밖에 둔다. 다만 줄 사이(26px × 1.6 = 41.6px 줄 높이)에 16px 글자가 끼면 다음 줄 윗부분과 겹치므로 꼬리표 쪽을 권한다. 어느 쪽으로 할지는 UX 판단.

### 1-4. 문제 그림이 칸 폭에 맞춰 늘어나서, 그림마다 선 굵기와 글자 크기가 달라진다 · 중간(⑤와 함께)
- 본 것: 8량 열차 그림(viewBox 폭 324)이 760px로 그려져 **2.35배**가 된다. 선 1.6 → 화면 3.8px, 그림 라벨 16 → 37px이 된다. 그림마다 viewBox 폭이 달라(수직선 380, 사람 274, 시간 띠 408, 시계 220) 배율이 제각각이다. 1차안 7절 "그림 공통 선 2px · 라벨 16px"이 화면에서는 지켜지지 않는다.
- 고칠 방법: 그림을 **고정 배율**로 그린다. 기준 기기에서 `K = 1.5`(작은 태블릿 1.25)로, `width = viewBox 폭 × K`, `max-width: 100%`. 더 넓은 칸은 여백으로 남긴다. 선 굵기는 그림 단위 2 → 화면 3px로 모든 그림이 같다. 라벨은 그림 단위 14 → 화면 21px, 숫자 라벨은 16 → 24px(문제 글자 26px보다 작게).
  ```css
  .figure { width: calc(var(--vbw) * var(--fig-k) * 1px); max-width: 100%; height: auto; max-height: none; }
  :root { --fig-k: 1.25; } @media (min-width: 1300px), (min-width: 900px) and (min-height: 1300px) { :root { --fig-k: 1.5; } }
  ```
  (`--vbw`는 그릴 때 `style="--vbw: 324"`로 넣는다.) `max-height: 180/220px`로 크기를 누르는 방식은 viewBox 비율에 따라 선이 다시 굵어지거나 가늘어지므로 뺀다.

### 1-5. 가로에서 운행 화면 아래 절반이 비어 있다 · 중간 — UX 판단 필요
- 본 것: 1480×924에서 문제 판·입력 판이 위쪽 약 300px만 쓰고, 도구 막대 위로 약 500px가 빈 바탕이다. 세로(924×1480)는 내용이 위 740px에 몰리고, 그 아래 약 650px가 비며, 키패드가 화면 가운데에 뜬다.
- 시각 제안(배치는 UX 결정): ① 가로는 B 판에 그림을 1-4의 고정 배율로 크게 두면 대부분 찬다. ② 세로는 **키패드와 답 내기를 화면 아래(도구 막대 바로 위)에 붙여** 손이 가는 곳에 두고, 문제와 그림이 위에서 남는 높이를 쓴다. ③ 세로 키패드는 3열이 820px로 퍼져 키 하나가 268×64다. 숫자 사이를 눈과 손이 멀리 오가므로 **키패드 최대 폭 480px**(키 약 150×72), 가운데 또는 손잡이 쪽으로 붙인다.

### 1-6. 홈의 "출발" 단추가 오른쪽 칸 폭의 1/4만 쓴다 · 쉬움
- 본 것: 출발 148×80, 옆에 급행 112·도전 154·차고 112(모두 72). 가장 중요한 단추가 가로로는 가장 작은 무리에 섞여 있다.
- 고칠 방법: 오른쪽 칸에서 출발은 **전체 폭 한 줄**(80px), 그 아래 줄에 급행·도전·차고를 같은 폭으로. 아이콘 `depart`를 글자 왼쪽에.

## 3. 그 밖에 본 것 (시각 밖, 참고로 전달)
- 정답을 냈는데 진행 칸이 그대로였다(첫 문제 `373 + 108`, "✓ 맞았어요"만). 3단계 미만 문제라 칸에 안 들어가는 것으로 보이지만, SPEC 3.4 "정답인데 화면이 그대로인 경우는 없다"(준비 구간 점)와 UX 05 P1-2(`· 한 칸 앞으로`)가 아직 화면에 없다. 진행 칸 옆에 **준비 점 3개**(지름 8, 채움 = `--fig-fill`)를 두면 ⑥ 칸 모양과 같은 문법으로 해결된다.
- 같은 오답을 두 번 내도 힌트 단추가 "권함"(4px + 채운 전구) 모양으로 바뀌지 않았다. 같은 값이라 두 번째가 세지 않은 것일 수 있다. 다른 값 두 번으로 다시 확인할 것.
- 시승 운행이 끝나 "운행 일지 보기"가 나온 뒤에도 도구 막대의 "아직 몰라요"가 눌린다.
- 운행 일지 "오늘 0 m 달렸어요 · 모두 0 m"(UX 05 P1-16과 같음).
- 고르기 문제의 답 내기 단추에 고른 답이 나오지 않는다("(가) — 답 내기", UX 05 P1-6 뒷부분). 숫자 문제는 `481명 — 답 내기`로 잘 나온다.

## 5. 추가 — "점검" 역 표시 (전략 세션 요청, bbe6d07 이후)
상황: 시승으로 추정해 켠 역에서 두 번 못 맞히면, 불은 그대로 두고 "점검" 상태가 된다.

**모양: 개통 역 그대로(흰 원 + 진한 테 + 노선 색 꼬리) + 바깥 점선 고리.** `map-marks.mjs`의 `stationMark(…, 'check', …)`.
- 크기: 확대(g ≥ 32) 고리 반지름 = 점 반지름 + 5(굵기 1.8, 점선 3/2.6), 중간(20 ≤ g < 32) + 3.5. 촘촘(g < 20)에서는 고리를 그리지 않는다(지름 0.8g 규칙). 1호선 전체 보기에서는 개통과 같게 보이고, 확대 보기와 역 시트가 알린다.
- 왜 이 모양인가
  - **선 문법**: 점선 = "아직(할 것이 남음)". 불(흰 점)은 그대로라 "꺼졌다·잃었다"로 읽히지 않는다(SPEC 2.2 "기록에 지울 수 없는 흠을 남기지 않는다", "줄어드는 수치 없음").
  - **공구 아이콘은 쓰지 않는다.** 공구(스패너)는 이미 "정비 완료"(회복 운행을 혼자 풀었을 때 받는 보상, SPEC 3.6)다. 같은 모양이 "점검이 필요해요"와 "정비를 마쳤어요"를 둘 다 뜻하면, 아이는 점검 역을 보상으로 읽거나 정비 완료를 지적으로 읽는다.
  - 느낌표, 경고 삼각, 빨강·노랑, 깜박임은 쓰지 않는다(실패 연출 금지). ≫ 자리에 쓰던 "점검" 글자도 지도에서는 뺀다(지도 글자는 역 이름만).
  - 통과역(≫)이 점검이 되면 ≫는 빼고 점선 고리만 둔다(한 점에 표시 하나).
- 흑백: 개통(고리 없음) / 점검(점선 고리) / 목적지(실선 이중 고리) / 확정(진한 채움) — 모두 다르다. 점검 고리는 **점선**, 목적지 바깥 고리는 **실선**이라 겹쳐 보이지 않는다.
- 역 시트 문구(UX 확인 필요): 제목 옆 `[점검]` 꼬리표(테 1.5, 16px) + "불은 켜진 채로 있어요. 다음에 이 역 문제를 한 번 더 풀어 봐요." 꼬리표 앞에 쓰는 아이콘이 필요하면 `info`(ⓘ).
- 운행 띠·일지: 점검 역이 임시 정차로 나오면 띠 꼬리표 `임시 정차 · 하단역`(지금 규칙) 그대로. "점검"이라는 낱말을 아이 화면에서 쓸지는 UX 판단 — 시각 쪽은 낱말 없이 점선 고리만으로 충분하다.
