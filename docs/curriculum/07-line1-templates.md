## 0. 공통 규약

### 0.1 정비창 곁가지 선로(B 노드)
- 템플릿은 **진단 문항만** 둔다(0.9절). 시승 운행이나 판별 오답에서 N01·N02·N05·N07의 선수 B 노드가 비어 보이면 진단 2문제로 확인한다. 둘 다 틀리면 엔진이 곁가지로 자동으로 들른다. 그 B 노드는 N 템플릿의 정비창 점검을 두 자리 수 범위로 줄여 연습한다.

### 0.2 템플릿 인터페이스
```
generate(seed, level) → { params, text, figure, input, answer, discriminators, level }
grade(problem, response) → { correct | reask | wrong, category, feedbackId, flags }
```
- `params`의 숫자는 모두 꼬리표를 단다:
  `{ v: 368, tag: "virtual" }` → 화면에 ✏ 와 점선 밑줄
  `{ v: 8, tag: "real", fact: "FACTS.md#1호선" }` → 누르면 출처와 확인 날짜
  `{ v: 4, tag: "math" }` → 계산에서 나온 수, 순수 계산 문제의 수(표시 없음)
- FACTS 대조 검사: `real` 꼬리표 숫자는 모두 FACTS.md ✅ 행에 있어야 한다. 빌드 검사가 `fact` 참조를 확인한다.
- `input`: `number` | `fraction` | `decimal` | `choice` | `multi`(여럿 고르기) | `paint`(칸 색칠) | `place`(톡-톡 놓기: 여러 개 고르고 칸 누르기) | `numberline`(점 찍기) | `cards`(숫자 카드 놓기) | **`equation`**(수 칸·연산 칩·수 칸 = 수 칸) | **`compound`**(이름 붙은 칸 여러 개, 칸마다 형식과 채점)
- **표현 태그**를 템플릿마다 단다: `그림` / `문장` / `식` / `빈칸`. 한 역에서 연달아 푸는 5문제에 표현 태그가 3가지 이상 섞이게 고른다.
- **도전 표시**: 장소와 관계없는 순수 계산 퍼즐(숫자 카드, □ 범위)은 `challenge: true`. 화면에 "도전 문제"로 보여주고 교통 이야기를 억지로 붙이지 않는다.

### 0.3 단계 공통 규칙
| 단계 | 바뀌는 것 |
|---|---|
| 1 | **한 단계 풀이**, 그림 있음, 가장 작은 수 범위, 필요 없는 정보 없음 |
| 2 | 두 단계(계산 + 검산·비교), 필요 없는 정보 없음 |
| 3 | 상황 판단 하나 |
| 4 | 거꾸로 생각(잘못 계산한 결과에서 바른 답, □ 구하기) |
| 5 | 조건의 범위(가능한 것 모두, 가장 큰·작은 것) |
| 6 | 표현이 바뀜(숫자 카드, 오류 찾기, 수직선, 다른 전체) |
| 7 | 두 조건 동시 + 모두 찾기 (천장이 7인 역만) |
- 1~6단계는 원문 해설·적용 시 고려 사항 안에서 만든다.

### 0.4 문제 문장 검수 체크리스트 (SPEC v0.7·v0.8)
1. 역 이름은 문제 안에서 실제로 쓰일 때만. 장식 금지.
2. **장소 일치**: 실제 장소 소재는 그 근처 역에만. 앞 10역(사하구)에서 쓸 수 있는 실제 값은 0.5절뿐이다.
3. 사실처럼 읽히는 설정도 사실이어야 한다. 확인 안 된 설정(예: 김해경전철 두 편성 연결)은 쓰지 않는다.
4. 뜻이 하나로 읽혀야 한다(예: "캡슐 하나에 320명"으로 잘못 읽힐 문장 금지).
5. 현실적인 숫자(한 반 128명 금지 → "1번 단체").
6. 몸풀기(1~2단계)에 필요 없는 정보 금지.
7. "잘못 계산한 수" 문제는 실수가 자연스러운 상황으로.
8. 헷갈리는 셈 말은 풀어 쓴다("일의 자리와 십의 자리에서 모두 받아내림").
9. 모호한 서수 금지("N정거장마다" + 예시 역).
10. 문제 속 숫자와 정답이 우연히 겹치지 않게(각 템플릿 `reject`).
11. 비계 질문은 문제가 아니라 힌트 ②에.

### 0.5 앞 10역에서 쓸 수 있는 실제 값 (FACTS.md ✅)
| 값 | 쓰는 곳 |
|---|---|
| 1호선 8량 | 칸 그림, 칸마다 나누기·곱하기, 분수 |
| 1호선 40역, 다대포해수욕장–노포, 39.9km | 역 수·정거장 간격, 소수 |
| 1호선 역 순서(다대포해수욕장, 다대포항, 낫개, 신장림, 장림, 동매, 신평, 하단, 당리, 사하, …) | 정거장 세기 |

- 다대포·낙동강 하구의 지리 값은 아직 FACTS에 없다. 추가되면 다대포해수욕장·다대포항·하단 역에서 쓸 수 있다.

### 0.6 채점 순서
```
1. 대충 낸 답: 0(정답이 0이 아닐 때) / 문제 속 숫자 그대로 → ⓘ "문제에 있는 수를 그대로 썼어요. 한 번 더 볼까요?" (분류 안 함)
2. 정답 → correct
3. 맞지만 형식이 다른 답 → reask (0.7절)
4. 판별 오답(각 템플릿) → wrong + 분류 + 피드백
5. 식 입력(equation)이 있으면: 식이 틀림 → 식 / 식은 맞고 값이 틀림 → 계산
6. 정답 ± 1 → (정거장 세기 문제면) 개념, 아니면 계산
7. 문제 속 다른 수로 만든 값(중간값 등) → 식
8. 그 밖 → 보류(고정 첫 줄만, 억지 피드백 없음)
```
- 같은 학생이 같은 `계산` 판별 오답을 두 번 내면 `개념`으로 올린다.
- 5초 안의 오답은 `flags.fast`. 5초 안에 고른 고르기 정답은 금 도장 없이 "정답"만(SPEC).
- `compound`는 칸마다 채점한다. 모든 칸이 맞아야 정답이고, 틀린 칸의 판별 오답으로 분류한다.

### 0.7 다시 묻기(reask)와 "상황과 다른 식" 판단
**맞지만 형식이 다른 답**(예: 2/8 = 1/4, "0.1km 15개")은 오답이 아니다. ⓘ로 다시 묻고, 바르게 쓰면 혼자 정답 한 칸(전략 세션과 UX가 정한 규칙). 단 **그 형식 자체를 배우는 역**에서는 바른 형식이어야 정답이다.

**상황과 다른 식**(예: "42명이 6칸에 똑같이 나눠 타면 한 칸에 몇 명?"에 42 ÷ 7 = 6이나 6 × 7 = 42를 쓰고 답 7)에 대한 판단 — **전략 세션 잠정안에 동의하고, 조금 넓힌다.**

| 경우 | 처리 | 이유 |
|---|---|---|
| 덧셈·곱셈의 순서만 바꾼 식(3 + 4 ↔ 4 + 3, 8 × 6 ↔ 6 × 8) | **어느 역에서든 정답** | 교환법칙. 3학년 교과서도 두 순서를 모두 받아들인다. 순서로 감점하면 아이가 이유를 모른다 |
| **N05 나눗셈의 의미, N06 곱셈과 나눗셈의 관계**에서 상황과 다른 나눗셈·곱셈식 | **reask**: ⓘ "이 식은 어떤 상황이에요? / 문제와 같나요?" 고치면 정답이되 **반 칸** | 이 두 역은 "식이 어떤 상황을 나타내는지"가 배우는 내용 자체다. ⓘ가 핵심을 짚었으므로 힌트 ②와 같은 무게로 센다 |
| N08 분수의 의미에서 분모가 등분 수와 다른 값이 같은 분수(2/8 ↔ 1/4) | reask, 고치면 정답 한 칸 | 값은 맞고, 등분 표현을 다시 확인하는 것뿐 |
| N10에서 "소수로 써요"에 분수를 씀(또는 반대) | reask, 고치면 정답 한 칸 | 형식을 배우는 역이지만 값의 이해는 맞음 |
| 그 밖의 역에서 `equation` 입력의 상황과 다른 식(값은 맞음) | **정답**. 다만 `flags.equationMismatch`를 기록 | 그 역의 목표는 계산·활용이다 |
| `equationMismatch`가 최근 10문제에 3번 | 다음 운행에 N05 또는 N06 임시 정차 1문제 | 식의 의미가 흔들린다는 신호. 벌이 아니라 복습으로 |
| 뺄셈에서 순서를 바꾼 식(작은 수 − 큰 수) | 어느 역에서든 오답(식) | 값이 달라진다 |

### 0.8 씨앗값과 단계 불변식 (F4)
- 단계는 **숫자 값이 아니라 구조**로 정한다(받아올림 횟수, 0의 위치, 문제 변형 종류, 묻는 것). 템플릿마다 `단계 불변식`을 적었다.
- 생성기는 씨앗값으로 숫자를 뽑은 뒤 불변식과 `reject` 조건을 검사하고, 어기면 다시 뽑는다(최대 50번, 넘으면 빌드 오류).
- 빌드 검사: 템플릿·단계마다 씨앗값 500개로 문제를 만들고 ① 불변식 분류기가 같은 단계를 돌려주는지 ② 정답이 채점 함수와 같은지 ③ 판별 오답 값이 정답·다른 판별 오답과 겹치지 않는지 ④ `real` 숫자가 FACTS에 있는지 확인한다.
- 임시 정차로 넘긴 문제는 **같은 템플릿·같은 단계·다른 씨앗값**으로 다시 낸다. 문장 틀이 같으면 아이가 답을 외운 것인지 알기 어려우므로, 단계 불변식이 같은 범위에서 수와 묻는 대상(예: 내리기 전 / 지금)을 바꾼다.

## 1. 다대포해수욕장 — N01 세 자리 수의 덧셈 [4수01-03]
천장 **6** · 선수 B06, B02 · 소재: 이 역과 다대포항역에서 타는 승객(✏), 1호선 8량

### T1-1 정비창 점검 (식) — 1~3단계
- 변수 a, b: 세 자리 수 100~899.
- **단계 불변식**: 받아올림 횟수 1단계 0~1, 2단계 2, 3단계 3(합이 네 자리).
- `reject`: a = b, 합의 끝자리가 a나 b의 끝자리와 같음.
- 정답 a + b.
- 판별 오답과 피드백:
  | 값 | 분류 | 피드백 |
  |---|---|---|
  | 자리마다 더하고 10을 버린 값 | 계산 | `일의 자리 10은 / 어디로 갔을까요?` |
  | 정답 − 10, 정답 − 100 | 계산 | `받아올린 1을 / 더했나요?` |
