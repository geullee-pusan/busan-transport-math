## 1. 지금 배포판의 시각 진단 — 학습 효율을 해치는 상위 5개

| 순위 | 문제 | 본 것 | 왜 학습에 해로운가 | 고칠 곳 |
|---|---|---|---|---|
| **1** | **상태가 선 모양이 아니라 '진한 채움' 하나로 뭉쳐 있다.** 고른 선택지(`.choice.chosen`), 고른 칩, 칠한 칸(`.paint-cell.on`), 답 내기(`.submit`), 출발(`.primary`)이 모두 진한 남색 채움 + 흰 글자다. 비활성은 `opacity: .45`로 글자까지 흐려진다(남색 위 흰 글자가 약 2:1로 떨어짐). | 운행 화면, `style.css` | 아이는 "진한 것 = 누르면 넘어가는 것"으로 배운다. 고른 답과 "답 내기"가 같은 모양이면 이미 냈다고 착각한다(UX 05 P1-6). 상태를 한눈에 알지 못하면 화면을 다시 읽느라 문제에 쓸 주의가 줄어든다. | 2.1절 **선 문법**, 5절 |
| **2** | **이모지 아이콘(💡🔊✎🚩⚙⏸)이 기기마다 다르게, 그리고 색으로 그려진다.** 크롬(윈도)에서 🚩는 빨간 깃발, 💡는 노란 전구, ⏸는 글자 "II"처럼 보인다. 삼성 인터넷·안드로이드는 또 다른 그림이다. 🔊 하나가 "읽어 주기"와 "소리 켬"을 둘 다 뜻한다. | 도구 막대, 피드백 줄, 홈 ⚙ | ① 빨강 깃발은 "틀림" 신호로 읽혀 정답·오답 무색 원칙을 깬다. ② 기기마다 모양이 달라 부모·형제 기기에서 설명이 안 맞는다. ③ 같은 그림 두 뜻 → 소리를 끄려다 읽어 주기를 누른다. ④ ⏸가 작고 흐려 오답 피드백의 '첫 신호'가 약하다. | 3절 아이콘 세트 |

| **5** | **문제 그림의 선·채움이 그림마다 다르고, 칠한 칸이 흐리다.** 선 굵기 0.6·1.2·1.4·1.5·1.6·2·2.5가 섞이고, 칠함 색 `#9FB3C1`은 흰 칸과 2.17:1(그래픽 기준 3:1 미달). 열차 칸 안에 옅은 창문 두 개가 칠함과 겹친다. 수 모형 1 모형이 8px, 100 모형 안 격자 0.6px. 그림 라벨 13px. | `figures.js`, 시승 문제 그림 | 분수·나눗셈 문제는 **칸을 세는 것이 곧 개념**이다. 칠한 칸이 흐리고 창문이 섞이면 아이는 세는 대신 짐작한다. 같은 '칸'이 그림마다 다르게 생기면 매번 그림 읽는 법을 다시 배워야 한다(인지 부하). | 7절 |

그다음으로 눈에 띈 것(6~8위): 차고 카드에 차량 그림이 없음(이름 앞 색 막대뿐, 그 색은 FACTS 근거 없음 — 6.3절), 내 차량 표지가 지도 위에서 노선 색과 겹침(아이가 주황을 고르면 1호선 위에서 사라짐), 초점 고리 색 `#1F6FB2`가 4호선·동해선 파랑과 겹침.

## 2. 디자인 토큰 (`assets/tokens.css`)

### 2.1 선 문법 — 이 체계의 뼈대
색 대신 **선 모양이 상태를 말한다.** 노선도·단추·카드·그림이 모두 같은 문법을 쓰면, 아이는 한 번 배운 읽는 법을 어디서나 쓴다(정답·오답 무색 원칙과 노선 색 보호를 동시에 지키는 방법).

| 선 | 뜻 | 쓰는 곳 |
|---|---|---|
| 점선 `- - -` (6/4) | **아직** | 꺼진 역 구간·개통 예정 노선, 못 얻은 카드, 아직 못 누르는 단추(답 칸이 빈 "답 내기"), 힌트 ④ 빈칸, 정비창 곁가지 |
| ~~점점이 `· · ·`~~ | ~~만든 숫자~~ | **쓰지 않음**(부모 결정 66f962e: 만든 숫자 표시를 아이 화면에서 뺌). 점점이 모양은 다른 뜻으로 다시 쓰지 않는다 |
| 실선 2px | **있음·누를 수 있음** | 기본 단추·칸·카드·그림 바깥선 |
| 굵은 실선 4px | **지금 고른 것·지금 채우는 칸·금테** | 고른 선택지(+✓ 배지), 키패드 대상 칸(+커서), 힌트 권함 단추, 그림의 짚는 표시, 금테 |
| 이중선 | **기록** | 역사 카드, 면허증 |
| 채움 | **끝남·확정** | 확정 역, 칠한 칸, 금 도장, 채운 진행 칸 |

- 굵기는 셋만: 400(본문) / 700(단추·숫자) / 800(제목, 켜진 역 이름, 답 칸 숫자). 문제 속 숫자는 700(지금처럼).
- **숫자 너비 고정을 앱 전체에**(`font-variant-numeric: tabular-nums`를 `:root`에) — 키패드·답 칸·표·km가 자리 맞춤으로 읽힌다.
- 줄 간격: 문제 1.6, UI 1.35. 한 줄 26자 안팎(기준 기기 30em까지 — style.css의 기준 기기 절과 같음).
- **글꼴: 시스템 한글 글꼴을 유지한다.** 형제 앱의 Pretendard Bold 부분 집합은 270KB(woff2)라 base64로 넣으면 지금 배포물(886KB)이 약 40% 커진다. 넣는다면 역명판(운행 띠의 "이번 역" 이름, 일지 제목)에만, 2단계에서 형제 앱과 같은 파일·같은 OFL 표시로(결정 필요 2). 지금은 이득보다 비용이 크다.

### 2.4 간격·둥글기·선·그림자
- 간격: 4px 바탕 `4 8 12 16 24 32 48`. 반대 동작 단추 사이 24px(SPEC 9.3).
- 둥글기 세 단계만: 6(작은 칸·세로셈·그림 칸) / 12(단추·입력 칸·카드) / 18(영역 판·시트 위) + 캡슐(꼬리표·두 글자 배지). 지금 14·16·18·12·8·6·4·3이 섞여 있다.
- 선 굵기 네 단계만: 1.5(배지 테두리·장식) / 2(기본) / 4(고름·대상·금테) / 노선 선 10(+속 7).
- **그림자는 쓰지 않는다.** 층은 테두리와 시트 뒤 덮개(`--scrim`)로만. 그림자는 흑백·햇빛 아래에서 사라지고, "떠 있음 = 누를 수 있음"을 일관되게 말하지 못한다. 형제 앱의 "관제실 화면" 느낌(평평하고 단정)과도 맞다.
- 움직임: 누름 100ms, 피드백 250ms, 차량 600ms(SPEC 9.3 그대로). 동작 줄이기면 모두 0.

### 3.1 규칙

## 4. 노선도 표지 (`assets/map-marks.mjs`)

> **갱신: 크기와 "지금 역" 고리는 `visual-review-02.md`(UX 6차 조율)가 이 절을 대신한다.** 모양 규칙(흰 원 + 진한 테, 확정 = 진한 채움, 개통 예정 색)은 그대로 확정.

### 4.2 ⚠ UX 문서와 다르게 제안하는 두 곳
1. **개통 역 = 노선 색 고리 → 큰 흰 원 + 굵은 진한 테두리**(ux-review-02 1.3, ux-05 P1-20과 다름). 켜진 역은 늘 켜진 노선 색 선로 위에 놓이므로, 노선 색 고리는 같은 색 선로에 묻힌다(견본에서 고리와 확정 원이 거의 같아 보였음). 실제 도시철도 노선도처럼 "색 선 위의 흰 점"이 가장 또렷하다. 노선 색은 이미 선로가 충분히 보여 준다. 확정은 "꽉 찬 원"(SPEC 9.5b) 그대로이되 진한 색으로 채워 흰 개통 점과 반대가 되게 했다.
2. **개통 예정 선 `#7A8691` 4px → `#5E6B76` 3px 점선**. `#7A8691`은 바다 위 2.41:1로 그래픽 기준 미달이다. `#5E6B76`은 바다 3.55, 육지 4.79, 산 3.60(높은 산 `#9DB38E`만 2.41 — 높은 산 위를 지나는 개통 예정 선이 실제로 있는지 확인 필요). 굵기를 줄여 1호선과 눈길을 다투지 않게 했다.

### 4.3 노선 선·확대 단계·누르기
- 켜짐: 테두리 10 + 노선 색 7 / 빈 선로: 테두리 10 + 흰 속 7 / 개통 예정: 4.2-2 / 정비창 곁가지: 진한 3px 점선.
- **선은 한 줄(path 하나)로 그린다.** 지금은 역 사이마다 선을 끊어 그려 둥근 끝이 겹친다. 역 점은 4.4의 확대 단계 규칙으로 줄인다.
- **확대 단계**(ux-review-02 1.4를 수치로): 지도 축척이 0.8보다 작으면(전체 보기) ① 아직 못 감 점과 그 이름을 그리지 않는다. 남는 것: 켜진 역, 목적지, 환승역, 종점. 배포판의 사다리 무늬가 이것으로 사라지고, 빈 선로가 "채울 자리"로 깔끔하게 보인다. 기준 기기 가로 홈(지도 칸 약 880×800)에서 1호선을 다 넣으면 축척이 약 1.0이라 모든 점이 보인다.
- **누르기**: 점 크기와 상관없이 누른 곳에서 가장 가까운 역(반경 24px)을 고른다(ux-05 P1-19와 같음). 누르는 영역을 점마다 따로 두지 않는다.
- 역 이름은 같은 쪽에 몰아 두고, 기준 기기에서 전체 보기 16px / 노선 확대 18px.

### 4.4 배지와 내 차량
- 배지: 한 글자 원 32px(글자 20 굵게), 두 글자 이상 캡슐 높이 32(글자 16 굵게, 흰 글자 대비 4.5 이상인 BGL·동해선만 해당). 카드·일지·지도 전체 보기 24px. 지금 지도 배지는 24px에 13px 글자 → 32px로.
- **내 차량 표지**: 흰 몸통 + 진한 테두리 2 + 바깥 흰 테 6(선로와 떼어 보임) + 아이가 고른 색은 **지붕 띠 4px에만**. 버스는 바퀴 둘, 열차는 진한 앞 유리. 앞이 진행 방향. 크기 30×18(기준 기기 36×22). 표지는 선로 **위에** 진행만큼의 자리에 놓는다(지금은 오른쪽 위로 14px 떠 있어 어느 구간인지 흐림). 정차 중이면 옆에 작은 ⏸ 원.

## 6. 차량 일러스트 체계 (`assets/vehicle-art.mjs`)

### 6.1 규칙
1. **옆모습, 앞이 오른쪽**(노선도 진행 방향과 같게).
2. **같은 부품으로만 그린다**: 몸통(흰 채움 + 진한 선 2px), 창 띠 하나(옅은 채움 + 1.5px — 낱낱의 창을 그리지 않음: 아이가 창을 셈), 진한 앞 유리(흑백에서도 앞이 보임), 바퀴(버스) 또는 대차(열차), 바닥 선.
3. **차량을 구분하는 것은 ① 원형 모양 ② 칸 수 ③ 이름 글자.** 색으로 구분하지 않는다.

### 6.3 단계별 카드 색(지금 `vehicles.js`의 `color`)

## 7. 문제 그림 시각 규칙 (`assets/figure-kit.mjs`)

원칙: **그림은 셀 수 있는 것만 또렷하게, 나머지는 지운다.** 그림이 판단을 대신하지 않는다(SPEC 9.5c)는 원칙은 그대로.

| 항목 | 지금 | 제안 |
|---|---|---|
| 바깥선(세는 대상) | 1.2 / 1.4 / 1.5 / 1.6 / 2 섞임 | **2px 하나** |
| 안쪽 나눔선 | 1.5~1.6 | 1.5px(띠 칸 경계, 넓이 모형 안쪽) |
| 보조 격자 | 0.6px `#C5D0D8`(안 보임) | 1px `#7A8691`(3.7:1) |
| 칠함 | `#9FB3C1`(2.17:1) | `#7F93A3`(3.18:1, 그 위 선 4.10) |
| 반 칸·일부 | 반반 칠(띠만) | 진한 빗금 2px/6px — 흑백에서 칠함·빈칸과 셋이 구분 |
| 짚는 표시(highlight) | 3px | **4px 테두리**(색 아님, 칠함과 함께 써도 구분) |
| 그림 라벨 | 13px | **16px**, 숫자는 굵게·고정폭 |
| 세는 칸 최소 | 34px(열차 칸) | 화면에서 40px 이상, 색칠 입력 56px(SPEC 9.4) |

그림 종류별
- **열차 칸**: 창문 없음(칠함과 겹치고 셀 거리만 늘림). 맨 앞 칸에 진한 앞 유리 하나로 방향만. 칸 사이 4px. 8칸 넘게 한 줄이 안 되면 4+4 두 줄(UX 04). 노선 색은 칸 아래 얇은 띠로만(그림이 어느 노선인지), 칠함 색으로 쓰지 않는다.
- **사람**: 머리 원 + 어깨 몸, 진한 채움(가장 또렷함), 22px 이상. **5명마다 틈**(한눈에 세기), 한 줄 10명. 고른 사람은 4px 테두리(색 아님). 칸 안 사람 수는 숫자로 쓰지 않는다(UX 04).
- **띠(분수)**: 높이 32, 바깥 2 / 칸 경계 1.5, 칠함 `--fig-fill`, 일부는 빗금. 비교하는 띠들은 같은 전체 길이, 왼쪽 맞춤.
- **수직선**: 본선 2px, 큰 눈금 16px·작은 눈금 10px(1.5px), 끝 눈금만 숫자(16px), 표시는 진한 삼각(위). 칠한 구간은 본선 위 8px 막대 `--fig-fill`.
- **수 모형**: 1 모형 한 변 화면 10px 이상(지금 8). 100 모형 안 격자 1px `#7A8691`. 100·10·1을 줄 사이 12px로 떼어 자리별 묶음이 보이게. 같은 단위끼리 5개마다 틈.
- **배열**: 칸 24px 이상, 틈 4px, 5칸마다 틈 8px. 둥근 네모(r 3) 흰 채움 + 2px.
- **넓이 모형**: 바깥 2, 안쪽 나눔 1.5, 변 길이 라벨은 바깥에 16px. 안에 곱(답)을 쓰지 않는다.
- **정사각형 나누기**: 120px 이상(지금 72), 두 줄 배치(UX 05 P2와 같음).
- **표**: 머리 행 굵게 + 아래 2px 선, 칸 선 1px `--soft`, 숫자 오른쪽 정렬·고정폭, 행 높이 48. 고른 행은 4px 테두리.
