# UX 자문 4차 — 실제 문제 화면 시안 (1호선 앞 10역 템플릿)

> 작성: UX 자문, 2026-10-04
> 근거: `docs/curriculum/07-line1-templates.md`, SPEC v0.8(칸 기준, 힌트 ① = 혼자, 정비창 자동), `ux-review-01~03`
> 화면은 태블릿 가로(약 1280×800) 기준. 영역 이름은 1차안과 같다: **A 진행 띠 / B 문제(왼쪽 60%) / C 입력(오른쪽 40%) / D 도구 막대**.
> 문제 숫자는 템플릿 예시 그대로다. 실제 값은 템플릿 0.5절(FACTS ✅) 범위에서만 썼다.

## 1. 공통 규칙 (네 시안 모두)

- **문제 문장**: 24px(1~4단계), 22px(5단계 이상), 줄 간격 1.6, 26자 안팎에서 어절 단위로 줄바꿈. 숫자와 단위는 붙여 둔다(`515석`).
- **"(가상)" 표시**: 문장 안 괄호로 쓰지 않는다 → 6절 규칙(점선 밑줄 + 숫자 출처 누르기).
- **입력 칸 크기**: 숫자 칸 높이 64px. 자리 칸 하나는 가로 48px. 분수 틀은 위·아래 칸이 각 56px.
- **키패드 대상 표시**: 키패드가 채우는 칸은 **굵은 테두리 3px + 커서**로 표시한다. 칸이 여럿이면 눌러서 바꾼다.
- **연습장 기본값**(4차 결정): 계산 = 세로셈 틀 / 길·도형 = 그림 위 투명 층 / 그 밖 = 옆 종이. D 막대에서 바꿀 수 있다.
- **답 내기**: C 영역 맨 아래 전체 폭, 72px. 답 칸이 하나라도 비어 있으면 누를 수 없고(흐린 모양), 누르면 "빈칸이 있어요"를 0.8초 보여준다(오답 처리하지 않음).

## 2. 문제 화면 시안 4종

### 2.1 [식] T3-1 정비창 점검 3단계 — 400 − 237 (세로셈 틀)

```
┌──────────────────────────────────────────────────────────────────┐
│ ✕ 그만   🏭 정비창 · 받아내림 점검   [■][■][ ]                   🔊 🔇 │ A
├─────────────────────────────────────────┬────────────────────────┤
│ B                                       │ C                      │
│   400 − 237 = ?            (32px, 가운데) │   답                    │
│                                         │   ┌──────────┐         │
│  ┌ 연습장: 세로셈 틀 ───────────── [바꾸기▾]┐│   │          │         │
│  │        ·    ·    ·   ← 받아내림 작은 칸  ││   └──────────┘         │
│  │      ┌───┬───┬───┐     (28px, 3개)      ││                        │
│  │      │   │   │   │   ← 빼어지는 수       ││   ┌───┬───┬───┐        │
│  │   −  ├───┼───┼───┤                     ││   │ 1 │ 2 │ 3 │        │
│  │      │   │   │   │   ← 빼는 수          ││   │ 4 │ 5 │ 6 │        │
│  │      ╞═══╪═══╪═══╡                     ││   │ 7 │ 8 │ 9 │        │
│  │      │   │   │   │   ← 계산한 줄         ││   │ ⌫ │ 0 │   │        │
│  │      └───┴───┴───┘     (각 48px)        ││   └───┴───┴───┘        │
│  │   백  십  일   (자리 이름 14px)          ││                        │
│  └──────────────────────────────────────┘│  [     답 내기     ]    │
├─────────────────────────────────────────┴────────────────────────┤
│ D   ✏ 연습장(세로셈)   💡 힌트                          ⚑ 이상해요 │
└──────────────────────────────────────────────────────────────────┘
```
- **문제는 가로식으로 낸다.** 세로셈 틀은 비어 있는 채로 둔다(수를 미리 채우지 않음). 수를 채워 두면 힌트 ②의 "길 고르기" 중 세로셈 하나만 밀어주는 셈이 된다.
- **세로셈 칸은 키패드로도, 펜(손가락)으로도 채울 수 있다.** 칸을 누르면 키패드 대상이 그 칸으로 바뀌고, C의 "답" 칸 테두리는 얇아진다. 초3은 손가락 글씨보다 키패드가 정확하다.
- **혼동 방지**: 세로셈 틀은 연습장이다. **채점은 C의 "답" 칸만 한다.** 세로셈 마지막 줄을 다 채우면 "답 칸에 옮겨 쓸까요? [옮기기]" 작은 단추가 나온다(자동으로 옮기지 않는다).
- 받아내림 작은 칸에는 숫자와 함께 **빗금(/)** 도 쓸 수 있다: 길게 누르면 그 위 칸 숫자에 빗금이 그어진다. 교과서 표기와 같다.
- 정비창 문제이므로 A 띠는 노선 구간 대신 정비창 점검 칸을 보여준다(7절).

### 2.2 [그림 + 문장] T3-2 3단계 — 김해경전철 두 편성

```
┌──────────────────────────────────────────────────────────────────┐
│ ✕ 그만   다대포항 ◉━[■][■][◧][ ]━○ 낫개 · 1칸 반 남음            🔊 🔇 │ A
│ ▕▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▏ 40역 중 2역 켜짐   │
├─────────────────────────────────────────┬────────────────────────┤
```

- **그림은 문장의 조건만 보여준다.** 두 편성이 이어진 모양 + 편성마다 184명. 합계 368은 그림에 쓰지 않는다(문장에 이미 있음, 그림이 계산을 대신하지 않게).
- 그림 속 차량은 김해경전철 실루엣(2량, 확인된 칸 수). 노선 색 `#895FA7`은 그림의 작은 띠에만 쓰고 숫자 글자는 진한 글자색.
- 3단계의 판단("두 편성 정원을 먼저")은 문장에 있다. 그림이 그 판단을 대신하지 않도록 **"368"을 그림에 다시 쓰지 않는다**.
- 단위 "명"은 답 칸 오른쪽에 고정 글자. 아이는 숫자만 넣는다.

### 2.3 [문장 + 표] T4-2 3단계 — 타고 내리는 승객

```
├─────────────────────────────────────────┬────────────────────────┤
│ B   ⓘ 만든 이야기                         │ C                      │
│  열차에 승객 245명이 있었어요.              │   답                    │
│  세 정거장을 지난 뒤 승객은 몇 명이에요?     │   ┌──────────┐ 명       │
│                                         │   └──────────┘         │
│  ┌───────────┬──────────┬──────────┐    │                        │
│  │ 정거장     │ ↑ 탄 사람 │ ↓ 내린 사람│    │   (키패드)              │
│  ├───────────┼──────────┼──────────┤    │                        │
│  │ 첫째      │    128    │     76    │    │                        │
│  │ 둘째      │     54    │    103    │    │                        │
│  │ 셋째      │     31    │     47    │    │                        │
│  └───────────┴──────────┴──────────┘    │  [     답 내기     ]    │
│   (숫자 오른쪽 정렬, 고정폭 숫자, 행 높이 48px)│                        │

```
(표의 숫자는 시안용 예시. 실제 값은 생성기가 만든다.)
- **표의 열 머리에 화살표 + 글자**: ↑ 탄 사람 / ↓ 내린 사람. 초록/빨강 같은 색 구분은 쓰지 않는다(1차 원칙 + 노선 색 충돌).
- **"승객 수" 열을 표에 두지 않는다.** 정거장마다 승객을 적는 칸은 힌트 ②에서만 보여준다(비계는 힌트로, 템플릿 0.4-5).
- 모든 수가 가상이라 숫자마다 밑줄을 긋지 않는다. **문제 맨 위에 "ⓘ 만든 이야기" 꼬리표 하나**만 둔다(6절).
- 표는 **행을 누르면 그 행에 굵은 테두리**가 생긴다(어디까지 계산했는지 표시용, 채점과 무관). 손가락으로 줄을 따라가는 습관을 화면이 받쳐 준다.
- 연습장 기본값은 "옆 종이"(표 문제는 '그 밖'). 표 위에 그리면 숫자를 가린다.

### 2.4 [그림 → 식] T5-1 — 똑같이 나누기 (1단계 그림, 2단계 식)

**1단계: 사람 놓기**
```
├─────────────────────────────────────────┬────────────────────────┤
│ B   ⓘ 만든 이야기                         │ C                      │
│  승객 24명이 8량에 똑같이 나눠 타요.         │   한 칸에 몇 명이에요?     │
│  사람을 칸에 놓아 보세요.                   │   ┌──────────┐ 명       │
│                                         │   └──────────┘         │
│  대기 줄: 👤👤👤👤👤👤👤👤👤👤👤👤          │                        │
│          👤👤👤👤👤👤👤👤👤👤👤👤 (남은 24) │   (키패드)              │
│                                         │                        │
│  ①[    ]②[    ]③[    ]④[    ]          │                        │
│  ⑤[    ]⑥[    ]⑦[    ]⑧[    ]  ← 1호선 8량 │  [     답 내기     ]    │
│      (칸 72×56px, 칸 번호 글자)            │                        │
├─────────────────────────────────────────┴────────────────────────┤
```
- **놓는 방법**: 대기 줄에서 사람을 누르면 선택(여러 명 연달아 선택 가능, 선택한 사람은 테두리), 칸을 누르면 선택한 사람이 그 칸에 들어간다. 끌기도 된다. 칸 안 사람을 누르면 대기 줄로 돌아간다.
- **칸 안 사람 수를 숫자로 보여주지 않는다.** 아이가 센다. 사람 아이콘은 칸 안에서 2줄 격자로 놓여 세기 쉽게 한다.
- "남은 24"는 대기 줄 숫자로 보여준다(놓을 사람이 몇 명 남았는지는 활동을 위한 정보라 괜찮다).
- **채점은 C의 답 칸만 한다.** 사람을 다 놓지 않아도 답을 낼 수 있다(머릿속으로 푼 아이를 막지 않음).
- 8량 그림은 두 줄(4+4)로 접어 그린다. 한 줄 8칸은 B 영역에서 칸이 너무 작아진다(칸 72px 유지).

**2단계: 식 입력 (F1 `equation`)**
```
│  4호선 열차는 6량이에요.                   │   식                     │
│  승객 4̲2̲명이 칸마다 똑같이 나눠 타요.       │  [ 42 ][ ÷ ▾][  6 ] = [ 7 ]│
│  식과 답을 써요.                          │                        │
│                                         │   답  [  7 ] 명          │
│  [4호선 6량 그림, 사람 없음]                │                        │
```
- 식 틀은 **수 칸 – 연산 고르기 – 수 칸 = 수 칸**이다. 연산은 + − × ÷ 네 개의 큰 칩(56px)에서 고른다. 기호를 키패드에 섞지 않는다.
- 식의 결과 칸과 답 칸이 같은 값이면 답 칸을 따로 둘 필요가 없어 보이지만, 템플릿 채점 4단계(식이 틀림 → 식 / 식은 맞고 값이 틀림 → 계산)를 위해 **식 = 값**을 한 줄로 받고, "답"은 단위가 붙는 문제에서만 따로 둔다.
- 받아 줄 식: `42 ÷ 6 = 7`. `42 ÷ 7 = 6`은 값은 맞지만 상황(칸 6개)과 다르다 → 채점 함수가 판단(커리큘럼 확인). 화면은 "6량에 나눠요. 나누는 수는 무엇일까요?" 한 줄 피드백 자리를 준비한다.

## 3. 입력 형식 보충 (F1)

### 3.1 `compound` — 이름 붙은 칸 여러 개
```
 T2-2 2단계:  더 많은 열차  ( 청룡 | 이음 )  ← 고르기 칩
              몇 석 더      [      ] 석
 T3-2 5단계:  가장 작은 수  [      ]
              그때 답        [      ]
 T10-1 3단계: 1km         [   ] 개
              0.1km       [   ] 개
```
- 칸마다 이름표를 왼쪽에, 단위를 오른쪽에 둔다. 칸 사이 간격 16px.
- 채점 결과는 **칸별로** 보여준다: 맞은 칸 옆 ✓, 틀린 칸만 ⏸. 틀린 칸만 비우고 맞은 칸은 남긴다(4차 결정 "틀린 답은 취소선"을 칸 단위로).
- T10-1 3단계 "0.1이 15개"처럼 다른 형식의 맞는 답: ⏸가 아니라 **ⓘ "다시 묻기" 상태**로 보여준다(4.4절).

### 3.2 `multi` — 모두 고르기 (T2-2 5단계 0~9 중 고르기, T7-2 5단계)
- 0~9 숫자 칩 10개를 두 줄(5+5), 칩 56px. 고른 칩 = 채움 + ✓ 모양(색만으로 구분 안 함).
- **"모두 골랐어요"를 따로 묻지 않는다.** 답 내기를 누르면 그대로 채점한다.
- 판별 오답(0~4만 고름) 피드백은 "경계에 있는 수도 넣어 봤나요?" 같은 한 줄. 몇 개가 빠졌는지는 말하지 않는다(4차: 개수 알려 주기 금지와 같은 원칙).

## 4. 힌트 서랍: 전략 고르기(②) → 고른 길의 ③ → ④ 빈칸

### 4.1 흐름 (T3-1 3단계 400 − 237)
```
 C 영역을 덮는 오른쪽 서랍 (B 문제와 세로셈 틀은 그대로 보임)

 💡 힌트                                         [닫기 ✕]
 ─────────────────────────────────────────────────
 ① 노선 확인                                     [접기]
    400에서 237을 빼요.
    일의 자리와 십의 자리가 모두 0이에요.
 ─────────────────────────────────────────────────
 ② 경로 안내
    어디까지 해 봤어요?                ← SPEC의 ② 관문
    [식 세우기] [첫 계산] [잘 모르겠어요]
          ↓ (하나 누르면)
    길이 여러 개예요. 편한 길을 골라요.
    ┌──────────────┐┌──────────────┐┌──────────────┐
    │ 세로로        ││ 237에서 400까지 ││ 399 − 237    │
    │ 받아내림하기   ││ 더해서 세기     ││ 먼저 하고 1 더하기│
    │  [세로셈 그림]  ││  [수직선 그림]  ││  [작은 식 그림] │
    └──────────────┘└──────────────┘└──────────────┘
      (카드 각 높이 120px, 그림 + 두 줄 글. 고른 카드 = 굵은 테두리 + ✓)
 ─────────────────────────────────────────────────
 ③ 중간 정류장   (②에서 길을 고르면 열림)
    [더해서 세기를 골랐어요 · 다른 길 보기 ▸]
    237 → 240은 3, 240 → 300은 60이에요.
 ─────────────────────────────────────────────────
 ④ 종착역 직전   🔒
    ④를 보면 숫자를 바꾼 문제로 한 번 더 해요.
```
- **② 관문과 길 고르기를 한 번에**: 관문 칩을 누르면 같은 자리에서 길 카드 세 개가 펼쳐진다. 화면 이동이 없다.
- **길 카드는 그림이 먼저**다. 글만으로 된 세 줄짜리 선택지는 초3이 읽지 않고 첫 번째를 누른다(서준 유형). 그림은 그 길의 첫 모양만 보여주고 계산은 하지 않는다.
- **길을 고르면 연습장 기본값도 그 길에 맞게 바뀐다**: 세로 → 세로셈 틀 / 더해서 세기 → 빈 수직선(237과 400만 표시, 눈금 없음) / 399 → 옆 종이에 `399 − 237 = ?` 한 줄. 아이가 그린 것은 지우지 않고, 새 판을 탭으로 추가한다.
- **다른 길로 바꾸기**: ③ 머리의 "다른 길 보기 ▸"로 길 카드에 돌아간다. 다른 길의 ③을 봐도 **힌트 사용 단계는 ③ 그대로**다(길을 바꾼다고 더 깊은 힌트로 치지 않음). 다른 풀이를 탐색하는 행동을 벌하지 않는다.
- 고른 길은 기록해 둔다(부모 화면 "도윤은 더해서 세기를 자주 골라요", 그리고 해설의 "다른 풀이"를 고른 길이 아닌 것으로 보여주는 데 쓴다 — 5절).
- 길 고르기가 없는 템플릿의 ②는 1차안처럼 글 + 필요한 그림만.

### 4.2 ②에서 그림이 바뀌는 비계
- T4-2의 "정거장마다 승객 적기", 바둑판 교차로 숫자 같은 비계는 서랍이 아니라 **B 영역의 그림 자체에 칸을 추가**한다. 서랍에는 "표 오른쪽에 승객 칸이 생겼어요. 채워 보세요"만 쓴다. 이 칸은 연습장과 같은 지위(채점 안 함)다.

### 4.3 ④ 빈칸 "1☐3" 표시 (F2 해결)
④를 열면 **C의 답 칸이 빈칸 틀로 바뀐다**.
```
 C  답
    ┌────┐┌┄┄┄┄┐┌────┐
    │ 1  ││ ▏  ││ 3  │    ← 1과 3은 고정 글자(회색 바탕, 누를 수 없음)
    └────┘└┄┄┄┄┘└────┘       가운데만 점선 테두리 + 커서 = 입력 칸
```
- 서랍에는 같은 모양의 식이 한 줄 보인다: `400 − 237 = [1][┆ ┆][3]`. 서랍과 답 칸의 빈칸이 같은 모양이라 "여기에 넣는다"가 분명하다.
- **문제 속 모르는 수 □**(7□2, 1/□)는 다른 모양으로 그린다: 실선 네모, 글자 높이, **옅은 회색 바탕**, 누를 수 없음. 힌트 빈칸은 **흰 바탕 + 점선 + 커서**. 문서의 □/☐ 글자는 화면에 그대로 쓰지 않는다.
- T9-2 ④ "□는 2, 3, ☐" 화면: `[□] 에 들어갈 수: 2, 3, [┆ ┆]` — 문제의 □는 회색 실선, 힌트 빈칸은 점선.
- T5-1 ④ "8 × ☐ = 24예요. 한 칸에 ☐명."처럼 같은 빈칸이 두 번 나오면, 두 빈칸을 **하나의 입력 칸으로 연결**한다(하나에 쓰면 다른 하나에도 같은 숫자가 보임, 점선 연결선).
- ④ 뒤의 쌍둥이 문제("회복 운행")는 SPEC대로. 빈칸 틀은 쌍둥이 문제에서 다시 일반 답 칸으로 돌아간다.

## 5. 피드백과 해설

### 5.1 피드백 위치와 길이
```
 C  답
    ┌──────────────┐
    │ 2̶6̶3̶           │  ← 틀린 답: 회색 취소선, 16px (4차 결정)
    │ ▏             │  ← 입력 칸은 비워 둠
    └──────────────┘
    ⏸ 버스가 잠깐 멈췄어요.
    백의 자리에서 100을 빌려 줬어요.
    4는 몇이 됐을까요?
```
- 자리: **C 영역, 답 칸 바로 아래.** 문제 영역(B)을 가리지 않는다. 피드백이 짚는 곳이 B에 있으면(예: 백의 자리), B의 문제 식에서 그 자리 숫자에 **밑줄(실선 3px)** 을 0.6초 그었다가 남겨 둔다(색이 아니라 모양).
- 길이: 첫 줄은 늘 `⏸ 버스가 잠깐 멈췄어요.`(고정). 그다음 **판별 피드백은 두 줄 이내, 한 줄 18자 안팎(C 폭 기준), 물음으로 끝나는 한 생각.** 정답이나 정답 숫자를 말하지 않는다.
- 템플릿 문구 중 길이 규칙을 넘는 것(줄여 쓰기 제안):
  | 템플릿 | 원문 | 제안 |
  |---|---|---|
  | T3-1 237 | 답이 빼는 수와 똑같네요. 400에서 237을 빼면 237이 될까요? 더해서 확인해 봐요 | `답이 빼는 수와 같아요.` / `더해서 확인해 볼까요?` |
  | T3-1 173 | 십의 자리는 빌려 받은 뒤 일의 자리에 다시 빌려 줬어요 | `십의 자리도 일의 자리에` / `빌려 줬어요. 몇이 남았나요?` |
  | T7-1 121·776 | 십의 자리 2를 먼저 3배 하고, 그다음에 올린 2를 더해요 | 정답 순서를 알려 주는 문장 → `올린 수는 언제 더했나요?` |
  | T9-2 1/8 | 같은 띠를 8칸으로 나누면 한 칸이 4칸으로 나눌 때보다 길까요? | `8칸으로 나눈 한 칸이` / `4칸으로 나눈 한 칸보다 길까요?` |
- **판별이 안 된 오답(보류)**: 고정 첫 줄만 보여준다. 억지 피드백을 붙이지 않는다.
- **대충 낸 답**(0, 문제 속 숫자 그대로): `문제에 있는 수를 그대로 썼어요. 한 번 더 볼까요?` — ⏸ 대신 ⓘ 모양. 오답 소리 없음. 빈칸은 1절대로 답 내기 자체가 안 된다.
- 두 번째 오답: 1차안대로 💡가 한 번 빛나고, 그 아래 작은 단추 `[임시 정차로 넘기기]`(다음 운행에서 다시 만나요). 이걸 누르면 문제가 끝난 것으로 보고 해설을 열 수 있다(F4).

### 5.2 "다시 묻기" 상태 (오답이 아닌 경우)
T10-1 3단계 "0.1km 15개", T8-1의 2/8(= 1/4)처럼 **맞지만 형식이 다른 답**.
```
    ⓘ 맞아요. 그렇게도 나타낼 수 있어요.
       1km와 0.1km로도 나눠 볼까요?
```
- ⏸가 아니라 ⓘ, 소리 없음, 취소선 없음(답 그대로 둠).
- 칸 진행: 커리큘럼 판단에 따름(제안: 정답으로 보고 칸 진행, 형식 다시 묻기는 칸과 상관없는 덤 문제).

### 5.3 해설 시트 "왜 그런지 / 다른 풀이 보기"
문제가 끝난 뒤(정답 또는 넘기기) C 영역 아래 단추 줄: `[왜 그런지] [다른 풀이 보기]  [다음 역으로 ▶]`.
```
 ┌ 아래에서 올라오는 시트 (화면 높이 60%, B 문제는 위에 보임) ───────────┐
 │  [ 왜 그런지 ]  [ 다른 풀이 ]         🔊             [닫기 ✕]       │ ← 탭
 │ ─────────────────────────────────────────────────────────────── │
 │  ┌──────────────┐                                                 │
 │  │ [100 묶음 4개  │   400은 100이 4개예요.                           │
 │  │  그림]        │                                                 │
 │  └──────────────┘                                                 │
 │                              ● ○ ○   [ 다음 ▸ ]                    │ ← 단계별 넘기기
 └───────────────────────────────────────────────────────────────────┘
```
- **한 번에 한 문장 + 그림 한 장.** 템플릿 해설은 2~3문장인데, 한 화면에 다 쓰지 않고 문장마다 넘긴다(● ○ ○). 하린 유형은 끝까지 넘기고, 서준 유형은 첫 장만 봐도 핵심을 얻는다.
- 그림은 문장마다 바뀐다: 400 = 100×4 → 100 하나를 10×10으로 → 10 하나를 1×10으로(묶음 블록 그림). 그림이 없는 문장은 식을 크게(32px) 쓴다.
- **"다른 풀이"는 아이가 고르지 않은 길을 먼저 보여준다**(4.1의 고른 길 기록). 힌트를 안 썼으면 템플릿의 "다른 풀이"를 그대로.
- 틀렸다가 넘긴 문제라면 시트 맨 위에 한 줄: `내 답 2̶6̶3̶ → 정답 163`. 다른 자리 숫자(6)에 밑줄. "틀렸어요" 같은 말은 쓰지 않는다.
- 문제 단계(차량 이름)는 시트에 보이지 않는다(3차 결정).
- 🔊는 시트 문장도 읽는다. "다음 ▸"를 누르면 다음 문장을 읽는다.

## 6. 실제 값과 지어낸 숫자 표시

> **최종 결정(전략 세션, SPEC v0.8 9.5c)**: 점선 밑줄 + 처음 세 번 "만든 숫자" 글자 + 모든 숫자 말풍선 + 모두 가상이면 "ⓘ 만든 이야기" 꼬리표. 학생 5차의 연필 ✏ 제안은 목적이 같고 문장을 덜 어지럽히는 점선 밑줄로 대신한다.
> 아래 6.1~6.1a는 연필 안을 검토한 기록이다. 구현은 **점선 밑줄**로 한다: 6.1 표의 "✏ 작은 아이콘"을 "점선 밑줄(1.5px 점, 숫자 아래 3px)"로, 처음 안내 문구를 `점선 밑줄 = 만든 숫자예요`로 읽는다. 누르는 영역(48px), 말풍선 문구, 🔊 규칙은 그대로 쓴다. 6.1a의 아이콘 충돌은 생기지 않으므로 연습장 아이콘은 ✏ 그대로 둔다.

### 6.1 규칙
| 문제 속 숫자 | 화면 표시 |
|---|---|
| **모두 실제**(FACTS ✅) | 표시 없음. 숫자를 누르면 출처 말풍선 |
| **섞여 있음** (예: "515석 중 278석") | 지어낸 숫자 오른쪽 위에 **✏ 작은 아이콘**(글자 높이의 60%, 14px) |
| **모두 지어냄** (T4-2 표처럼 숫자가 많음) | 숫자마다 ✏를 붙이면 표와 문장이 ✏로 뒤덮인다 → **문제 맨 위 꼬리표 하나 `✏ 이 문제의 숫자는 모두 지어냈어요`**. 숫자를 누르면 같은 말풍선(제안, 학생 확인 권장) |

```
  KTX-청룡 515석 중 278✏석에 사람이 앉았어요.
```
- ✏는 숫자와 단위 **사이**가 아니라 숫자 **오른쪽 위 어깨**에 붙인다(`278✏석`이 "278 연필 석"으로 읽히지 않게, 위첨자 위치). 줄바꿈으로 숫자와 떨어지지 않게 묶는다.
- **누르는 영역**: ✏ 아이콘만 누르면 너무 작다(14px). **숫자 + ✏ 전체를 48px 영역**으로 잡는다. 실제 숫자도 같은 크기 영역.
- 말풍선:
  - 실제: `KTX-청룡 좌석 515석` / `출처: (FACTS.md 출처 기관) · 2026년 10월 확인`
  - 지어냄: `문제를 위해 지어낸 숫자예요.`
- 처음 안내(한 번): 첫 ✏ 문제에서 ✏ 옆에 말풍선 `✏ = 지어낸 숫자예요. 진짜 숫자는 눌러서 출처를 볼 수 있어요.` 아무 데나 누르면 닫힘.
- 그림 속 숫자도 같은 규칙.
- 🔊 읽어주기: "연필"이나 "가상"을 읽지 않는다. 처음 세 번만 문제 끝에 `연필 표시가 있는 숫자는 지어낸 숫자예요`.

### 6.1a ⚠ 아이콘 충돌: ✏는 이미 연습장 단추다
1차 시안부터 D 막대의 연습장 단추가 `✏ 연습장`이다. 같은 연필이 "지어낸 숫자"와 "연습장"을 함께 뜻하면 아이가 숫자 옆 ✏를 눌러 연습장이 열리길 기대하거나 그 반대가 된다.
- 제안: **연필은 지어낸 숫자에 양보하고, 연습장 단추는 공책 모양(📓 모양의 선 그림 아이콘) + "연습장" 글자**로 바꾼다. 하린이 고른 상징을 살리는 쪽이 낫다. 이 문서의 시안 그림 속 `✏ 연습장`은 모두 `📓 연습장`으로 읽어 주세요.

### 6.2 하린 유형이 믿게 만드는 장치
- **표시가 거짓말을 하지 않는 것이 가장 중요하다.** 확인된 값(515석, 8량)에 가상 표시를 붙이지 않고, 가상 값에는 빠짐없이 붙인다. 생성기 단계에서 숫자마다 `real: factId | virtual` 꼬리표를 달고, 문장을 만들 때 그 꼬리표로 밑줄을 그린다(손으로 쓰지 않음). 검사 스크립트: 문제 안 모든 숫자가 꼬리표를 가졌는지.
- 출처 말풍선의 날짜는 FACTS.md의 기준일을 그대로 쓴다.
- "이 문제 이상해요" 신고 시트의 이유 칩 "부산 사실이 틀려요"를 누르면, 그 문제의 실제 값 목록이 함께 저장된다(부모 화면에서 어느 값을 의심했는지 보임).

## 6.5 학생 5차 결정의 화면 반영

### 6.5.1 어림 먼저 (T4-1형)
```
 C  대충 몇백쯤일까요?
    [ 약 [     ] ]          ← 먼저 열림. 키패드
    ─────────────
    정확히 계산하면?
    [     ]  어림을 먼저 써요    ← 닫힌 칸: 흐린 테두리 + 글자 안내(자물쇠 아이콘 없음)
```
- 어림 칸을 채우고 `[어림 확인]`을 누르면 계산 칸이 열린다. 어림 칸 채점은 **넓게**(몇백 단위로 합리적인 값 모두 인정, 범위는 생성기가 정함). 어림이 많이 벗어나도 ⏸ 대신 ⓘ `계산한 뒤에 어림과 비교해 봐요`를 보여주고 계산 칸은 연다. 어림 칸에서 막혀 진행이 끊기면 안 된다.
- 계산 칸이 열린 뒤에는 어림 칸을 고칠 수 없다(취소선 없이 잠김). 계산 결과와 어림을 거꾸로 맞추는 것을 막는 것이 5차 결정의 목적.

### 6.5.2 힌트 ④ 빈칸 → 판단 질문 순서 (T4-1 3단계)
- ④ 빈칸 틀 `245 + 96 = 3[┆ ┆]1`을 맞게 채워야 아래에 판단 질문 `320명보다 많을까요, 적을까요? [많아요][적어요]`가 나타난다. 빈칸이 틀리면 일반 오답 흐름. 판단 질문은 그 전에는 **보이지 않게**(흐리게 보여주면 먼저 누르려 함).

### 6.5.3 고르기 문제의 "어떻게 어림했어요?"
- 선택지 위에 한 줄 입력 칸: `어떻게 어림했어요?` — 식이나 수를 쓰는 칸(예: `500 + 400`). 키패드에 +, − 키를 이 칸에서만 추가.
- 이 칸이 비어 있으면 선택지를 누를 수 없다. 내용은 채점하지 않고 기록만 한다(부모 화면, 해설에서 "내 어림"으로 보여줌). 아무 숫자나 쓰는 꼼수는 막지 못하지만 **한 번 멈추게 하는 것**이 목적이라 충분하다.

### 6.5.4 ⚠ "5초 안에 고른 정답은 금 도장 없이" — 반대
- SPEC 2.2 표의 금지 항목 "시간 측정을 보상에 쓰는 것"과 정면으로 부딪힌다. 3차 학생 라운드에서 하린이 가장 싫어한 것도 "몰래 시간을 재는 느낌"이었다. 금 도장이 가끔 빠지는 이유를 아이가 알아내는 순간, 앱 전체에 대한 신뢰가 떨어진다.
- 6.5.3의 "어떻게 어림했어요?" 칸이 이미 빨리 찍기를 막는다. 어림 칸을 채우는 데 5초 이상 걸리므로, 5초 규칙은 거의 효과가 없고 위험만 남는다.
- 제안: 5초 규칙은 **보상에서 빼고**, 기존처럼 `flags.fast`로 부모 화면 주간 경향에만 쓴다. 꼭 남겨야 한다면 아이에게 규칙을 공개해야 한다(숨긴 규칙 금지). 그런데 공개하면 "타이머"가 되므로 SPEC과 다시 부딪힌다.

### 6.5.5 힌트 ② 두 문장 이내
- 서랍의 ② 글 영역을 **최대 2문장, 3줄**로 고정한다. 넘치면 렌더러가 경고(검수용). 길 고르기 카드가 있는 ②는 "편한 길을 골라요" 한 문장 + 카드 그림으로 끝낸다. 길 이름은 카드 안 두 줄이라 문장 수에 세지 않는다.
- 07 템플릿의 ② 중 세 문장 이상인 것(T1-2 ②, T2-2 ② 등)은 커리큘럼 쪽 문구 수정 대상.

### 6.5.6 해설 시트의 끝
- 5.3절의 단계별 넘기기에서 **마지막 장은 늘 결론 한 문장**(32px 식 + 한 줄): `그래서 400 − 237 = 163이에요.`
- [다른 풀이] 탭의 마지막 장에는 확인 문장을 붙인다: `세로셈으로 해도, 399를 써도 답은 163으로 같아요.` 두 풀이를 나란히 작게(왼쪽 = 고른 길, 오른쪽 = 다른 풀이) 보여주고 두 답에 같은 밑줄.
- 받아내림 해설 그림: **일 → 십 → 백** 순서로 "빌려 오기"를 보여주는 자리 칸 그림. 장마다 화살표 하나(백 → 십 → 일 방향으로 묶음이 풀려 내려감). 100 묶음 블록이 10 묶음 10개로 풀리는 그림은 동작 줄이기 설정에서도 정지 그림 3장으로 보여줄 수 있게.

### 6.5.7 세로셈 틀
- 받아내림이 두 번 이상인 문제(T3-1 전 단계, T3-2)에서는 연습장 기본값을 세로셈 틀로 **고정**(바꾸기 단추는 남김). 2.1절 시안 그대로.

## 7. 정비창 자동 들르기와 돌아오는 연출

### 7.1 언제
- 시승 운행이나 목적지 결정 시점에 엔진이 "목적지 역의 B 선수를 아직 못 익힘"을 알면, **운행이 시작되기 전(홈에서 출발을 누른 직후)** 들른다. 운행 중간에 끼우지 않는다(문제 흐름이 끊기고, 3~4번 어려운 문제 직전에 끼면 서준이 이탈).

### 7.2 화면 순서
```
 ① 출발 직후, 홈 지도 위 시트 (선택지 없음, 단추 하나)
 ┌──────────────────────────────────────────────┐
 │  🏭  동매역 가기 전에                          │
 │      정비창에서 곱셈구구를 점검해요.             │
 │                                              │
 │      [  정비창으로  ]                          │  ← 누를 때 시작(자동 진행 금지 원칙)
 └──────────────────────────────────────────────┘

 ② 지도 연출 (1.2초): 장림–동매 구간의 차량 → 곁가지 점선이 그려지며 → 정비창 아이콘으로 들어감
    동작 줄이기면: 곁가지 점선만 나타나고 바로 정비창 화면

 ③ 정비창 문제 화면: A 띠 = 🏭 정비창 · 곱셈구구 점검  [■][■][ ]  (점검 칸)
    - 문제는 B 노드 1~3단계 맨 계산(템플릿 0.1절). 이야기 문장 없음.
    - 점검 칸 수는 B 노드 숙달 기준에 맞춤(커리큘럼 결정, 시안은 3칸).
    - 점검 칸을 다 채우면 그 운행은 끝나지 않고 ④로.

 ④ 돌아오는 연출 (1초): 정비창 → 곁가지 → 원래 구간의 차량 자리로 돌아옴
    곁가지 점선이 사라지고, 정비창 아이콘 아래 선로 이름 옆에 ✓
    시트: "정비 완료 — 동매역으로 다시 출발해요"  [ 출발 ]
```
- 운행 일지에는 `정비창: 곱셈구구 점검 ✓` 한 줄(① 새로 켜진 역 자리에 넣음). 큰 소식 자리는 "정비 완료"를 쓰지 않는다. 정비창만 다녀온 운행이면 큰 소식 = `동매역으로 갈 준비가 됐어요`.
- km는 절반(전략 세션 결정). 일지에서 따로 "정비 거리"라고 구분하지 않고 그냥 오늘 km에 합친다(절반이라는 사실을 강조하지 않음).
- **점검을 한 번에 못 마치면**: 운행 6문제 안에 점검 칸을 다 못 채운 경우 → 그 운행은 정비창에서 끝나고, 일지 제목은 `정비창에서 곱셈구구 점검 중`. 다음 운행은 정비창에서 이어서(①의 시트 문구: `정비창 점검을 이어서 해요`).
- 필수가 아닌 점검을 제안할 때(SPEC: `[정비창 들르기][그냥 갈래요]`)도 ①과 같은 시트에 단추만 두 개. 두 단추는 같은 크기.

## 8. 결정이 필요한 것
1. **F1**: `equation`, `compound` 입력 형식 추가(커리큘럼 인터페이스).
2. **F2**: 문제의 □와 힌트 빈칸을 다른 모양으로 그리는 규칙 — 템플릿 문서 표기는 그대로 두고 렌더러가 구분.
3. **F3**: 힌트 ① 문구 점검 기준과 T7-1·T6-1·T1-2 ① 다시 쓰기.
4. **F4**: 해설은 문제가 끝난 뒤에만, 넘긴 문제는 다른 씨앗값으로 임시 정차.
5. 상황과 다른 식(42 ÷ 7 = 6)을 받을지 — 채점 함수 규칙.
6. 형식만 다른 맞는 답("0.1이 15개")의 칸 진행.
7. 정비창 점검 칸 수(B 노드 숙달 기준).
8. 피드백 문구 길이 규칙(두 줄 이내, 18자 안팎, 물음 하나) — 템플릿 피드백 전체에 적용할지.
9. ~~연습장 아이콘 바꾸기~~ — 점선 밑줄로 확정되어 필요 없음.
10. ~~모두 지어낸 문제의 표시~~ — "ⓘ 만든 이야기" 꼬리표로 확정.
11. **"5초 안에 고른 정답은 금 도장 없이" 철회 제안** — SPEC 2.2 위반, 6.5.4.

> 참고: 시안 속 예시 문제(스카이캡슐·신장림, 김해경전철 두 편성)는 커리큘럼 쪽에서 바뀔 예정이다. 이 문서는 화면 구조 기준으로 읽는다.
