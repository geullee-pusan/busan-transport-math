## 1. 저작권 규칙
- 문제 문장을 그대로 옮기지 않는다. **유형·구조·발문 방식·흔한 오답만** 추상화해 기록한다. 예시가 필요하면 숫자와 장면을 바꾼 우리 문장으로 쓴다.
- 출처는 이름과 링크로만 남긴다. 유료·로그인 자료는 열지 않는다. 문제집은 공개 목차의 유형 이름 수준까지만 본다.

## 2. 분류 기준 (세 축)
유형 하나는 **주 노드 × 구조군 × 단계** 세 축으로 자리를 잡는다.

### 2.1 주 노드 (커리큘럼 세션 기준 ①)
- `concept-graph.json`의 노드 id(N·G·R·D·X·B)를 단다.
- 여러 노드에 걸치면 **그 유형이 가르치는 핵심 아이디어가 있는 노드 하나**를 주 노드로 정한다. "풀 수 있는 도구"가 아니라 "핵심 아이디어" 기준이다(`docs/curriculum/04-difficulty-ladder.md` 3절). 예: 나눗셈 역에서 "나누어떨어지게 하는 수를 모두"는 약수 N31, 덧셈 역의 복면산은 X06.
- 걸친 노드는 `함께` 칸에 적는다. 주 노드가 우리 역이 아니면 그 노드로 **보낼 유형**으로 표시한다.
- 초등 성취기준에 없는 내용(경우의 수, 비둘기집 원리 등)은 동해선 X 노드로 보낸다.

### 2.2 구조군 (무엇을 주고 무엇을 묻나)
같은 노드 안에서 빠진 유형을 찾을 때 쓴다. 웹 유형 이름이 문제집마다 달라서 구조로 다시 묶는다.

| 기호 | 구조군 | 무엇을 주고 무엇을 묻나 | 예 |
|---|---|---|---|
| C | 계산 | 식 → 값 | 352 − 127 |
| M | 의미·표현 바꾸기 | 그림·말·식·수직선 사이 옮기기 | 수 모형 → 식, 0.1이 □개 |
| F | 정방향 문장제 | 상황 → 식 → 값 | 탄 사람 모두 몇 명 |
| B | 거꾸로 | 결과 → 처음 수, □ 구하기, 잘못 계산한 값에서 바른 값 | 내리고 남은 수 → 처음 |
| J | 비교·판단 | 두 양 비교, 예/아니요, 알맞은 것 고르기 | 탈 수 있나요 |
| R | 조건 범위 | 가능한 것 모두, 가장 큰·작은 것 | □에 들어갈 수 모두 |
| E | 오류 찾기·설명 | 틀린 풀이 고치기, 이유 고르기 | 세로셈에서 틀린 곳 |
| P | 숫자 카드·퍼즐 | 카드로 수 만들기, 복면산, 수 배열 | 합이 가장 큰 두 수 |
| A | 어림·수 감각 | 계산 전에 대강, 답이 맞는지 가늠 | 대충 몇백쯤 |

### 2.3 단계 (커리큘럼 세션 기준 ②)
- `04-difficulty-ladder.md` 1절의 11단계 기준표(풀이 단계 수 / 비정형성 / 융합 / 수 크기 / 표현)로 매긴다. 단계마다 **근거 축**을 짧게 적는다(예: `4: 거꾸로`, `5: 범위`).
- 1~6단계는 2022 개정 원문 **해설·적용 시 고려 사항 안의 것만**. 그 범위를 넘으면 7단계 이상으로 매긴다.
- 역마다 천장(`ceiling`)을 넘는 유형은 동해선이나 다음 역으로 보낸다.

### 2.4 풀이 도구 (커리큘럼 세션 기준 ③, 7단계 이상만)
- 그 노드와 선수 노드의 도구(목록, 표, 그림, 거꾸로 풀기, 수직선, 하나씩 확인)로 풀리면 `✓` + 도구 이름.
- 선수 밖 공식이 있어야 풀리면 그 공식의 노드를 적고, 초등 밖이면 `→ X노드`.

## 3. 기록 항목 (유형 한 줄)
| 항목 | 쓰는 법 |
|---|---|
| 유형 id | `<주 노드>-W<번호>` (예: `N15-W04`). 번호는 한 번 주면 바꾸지 않는다 |
| 유형 이름 | 짧은 우리말 이름(문제집 유형 이름을 그대로 쓰지 않음) |
| 주 노드 / 함께 | 2.1절 |
| 성취기준 | `4수01-06` 등 |
| 구조군 | 2.2절 기호 |
| 구조·발문 방식 | 주는 것 → 묻는 것, 풀이 단계 수, 묻는 말의 모양(예: "~은 모두 몇", "□ 안에 들어갈 수 있는 수를 모두") |
| 표현·입력 | 그림/문장/식/빈칸 + 입력 형식(number, choice, compound…) |
| 단계 | 2.3절 숫자 + 근거 축 |
| 범위 | `원문 안` / `넘어섬(7+)` |
| 풀이 도구 | 2.4절(7단계 이상만) |
| 흔한 오답 | 값의 모양 → 분류(식·계산·읽기·개념). 판별 오답 후보 |
| 교통 장면 | 옮길 장면과 숫자 꼬리표 계획(real/virtual/가정/math) — `03` 절차 |
| 출처 | 출처 번호(문서 맨 위 출처 목록) |
| 우리 템플릿 | `있음`/`부분`/`없음` + 템플릿 id |
| 상태 | `수집` → `검토` → `제안` → `템플릿화` / `보류`(이유) |

## 4. 작업 규칙
- 유형 은행은 역(노드) 순서로 계속 보강한다. 같은 유형을 다시 찾으면 출처 번호만 더한다.
- 빠진 유형은 우선순위(상·중·하)와 이유를 붙여 제안한다. 템플릿 설계(07·08 문서 형식)는 커리큘럼 세션과 함께 정한다.
- 문체 검토는 **생성기를 실제로 돌려 뽑은 문장**으로 한다(`scripts`가 아니라 검토용 일회 스크립트, 씨앗값 = `hashSeed(템플릿 id, 단계, i)`). 검토 기준 커밋을 문서 맨 위에 적는다.
